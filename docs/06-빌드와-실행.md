# 06. 빌드와 실행

## 요구 사항

| 항목 | 필요 버전 | 비고 |
|---|---|---|
| .NET SDK | **10.0** 이상 | 이 환경 확인 결과: `10.0.400` 설치됨 |
| OS | Windows | 레지스트리 API 의존 (`Microsoft.Win32.Registry`) |
| IDE | 선택 사항 | Visual Studio 2022+ / Rider / VS Code + C# Dev Kit |

솔루션 파일이 **`.slnx` 형식**(새 XML 기반 솔루션 포맷)이라 구버전 도구는 열지 못할 수 있습니다. 그럴 때는 `.csproj`를 직접 열면 됩니다.

## 빌드

```bash
dotnet build "H:/source/repos/steam game tool/steam game tool.slnx"
```

릴리스 빌드:

```bash
dotnet build "H:/source/repos/steam game tool/steam game tool.slnx" -c Release
```

## 실행

```bash
dotnet run --project "H:/source/repos/steam game tool/steam game tool/steam game tool.csproj"
```

빌드 산출물을 직접 실행하려면:

```
steam game tool\bin\Debug\net10.0-windows\steam game tool.exe
```

## 단일 파일로 배포

의존성 없이 exe 하나로 뽑을 때:

```bash
dotnet publish "H:/source/repos/steam game tool/steam game tool/steam game tool.csproj" -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

산출물 위치: `steam game tool\bin\Release\net10.0-windows\win-x64\publish\`

`IncludeNativeLibrariesForSelfExtract`가 없으면 `av_libglesv2.dll`, `libHarfBuzzSharp.dll`, `libSkiaSharp.dll`이 exe 옆에 따로 생깁니다. 넣으면 exe 하나(약 100MB)만 남습니다. 옆의 `.pdb`는 디버그 기호라 배포할 때 빼도 됩니다 (2026-09-22 확인).

> 이 도구는 **레지스트리를 읽기만 하고 파일을 쓰지 않으므로** 관리자 권한이 필요 없습니다. 다른 사용자 계정 소유의 Steam 라이브러리를 스캔하려는 경우에만 권한 문제가 생길 수 있습니다.

## 사용 흐름

1. **「폴더 ▸ 자동 감지」를 먼저 눌러 봅니다.** 상태 줄에 찾아낸 `steamapps\common` 경로들이 표시됩니다.
   - 아무것도 안 나오면 → 「폴더 ▸ 찾아보기…」로 `common` 폴더를 직접 지정
2. **「스캔 시작」** — 진행 상황이 상태 줄에 게임 이름으로 흐릅니다
3. **「보기」 콤보박스**로 원하는 마커만 걸러 봅니다
4. **「저장 ▸ TXT로 저장…」** — 현재 필터에 걸린 목록을 파일로 내보냅니다
5. **「저장 ▸ 6개 모두 저장…」** — 보기 목록 6개를 고른 폴더에 한 번에 저장합니다 (같은 이름 파일은 덮어씀)

실제 라이브러리(게임 885개) 기준 스캔은 **약 0.7초**에 끝납니다. 중간에 취소할 방법은 아직 없지만([07-개선 로드맵](07-개선-로드맵.md) 5번), 이 속도에서는 필요할 일이 거의 없습니다.

## 테스트

```bash
dotnet test "H:/source/repos/steam game tool/steam game tool.slnx"
```

판별 로직을 건드렸다면 **반드시 돌려 보세요.** 테스트 34개가 [04-판별 로직](04-판별-로직.md)의 규칙을 하나씩 고정하고 있습니다. 자세한 구성은 [05-코드 레퍼런스](05-코드-레퍼런스.md)「SteamGameTool.Tests」를 보세요.

## 개발 도구

Debug 빌드에서만 Avalonia DevTools가 활성화됩니다 (`Program.cs:18`, `WithDeveloperTools()`).

실행 후 **F12**를 누르면 비주얼 트리 검사기가 열립니다. 레이아웃이나 바인딩 문제를 볼 때 씁니다.

Release 빌드에서는 `AvaloniaUI.DiagnosticsSupport` 패키지가 `IncludeAssets=None`으로 빠지므로 (`steam game tool.csproj`) 산출물에 포함되지 않습니다.

## 문제 해결

### 빌드가 깨진다

| 증상 | 원인 | 해결 |
|---|---|---|
| `net10.0-windows`를 찾을 수 없음 | .NET 10 SDK 미설치 | `dotnet --list-sdks`로 확인 후 설치 |
| 바인딩 관련 컴파일 에러 | 컴파일드 바인딩이 켜져 있음 | `DataTemplate`에 `x:DataType`이 있는지, 바인딩 경로 오타가 없는지 확인 |
| `.slnx`를 못 연다 | 구버전 IDE | `.csproj`를 직접 열기 |

### 실행은 되는데 결과가 이상하다

| 증상 | 확인할 것 |
|---|---|
| 「자동 감지」가 아무것도 못 찾음 | Steam이 설치돼 있는지, 레지스트리 `HKCU\Software\Valve\Steam`에 `SteamPath`가 있는지 |
| 게임이 목록에 안 나옴 | 「전체」 필터는 **마커가 있는 것만** 보여 줍니다 ([04-판별 로직](04-판별-로직.md)「오탐과 미탐」) |
| 백엔드 판정이 틀린 것 같음 | [04-판별 로직](04-판별-로직.md)의 「판정을 직접 확인하는 법」으로 대조 |
| 배지가 전부 회색 | 두 곳이 `TagNames` 상수를 공유하므로 이제는 일어나지 않아야 합니다. 발생하면 새 태그를 상수 없이 추가했는지 확인하세요 |
| 스캔이 너무 느림 | 게임 885개 기준 1초 안에 끝나야 정상입니다. 훨씬 오래 걸리면 네트워크 드라이브나 느린 외장 디스크를 스캔하고 있는지 확인하세요 |
| 상태 줄에 "읽지 못한 폴더 N개" 경고 | 권한 문제 등으로 일부 폴더를 열지 못했습니다. 결과가 누락될 수 있습니다 |

### 레지스트리를 직접 확인하기

```bash
reg query "HKCU\Software\Valve\Steam" /v SteamPath
```

라이브러리 목록을 직접 보려면:

```bash
grep -o '"path"[^,]*' "$(reg query 'HKCU\Software\Valve\Steam' /v SteamPath | grep SteamPath | awk '{print $3}')/steamapps/libraryfolders.vdf"
```
