# 06. 빌드와 실행

명령은 모두 저장소 최상위 폴더에서 실행합니다.

## 요구 사항

| 항목 | 필요 버전 | 비고 |
|---|---|---|
| .NET SDK | **10.0** 이상 | 개발 PC에는 `10.0.400` 설치 |
| OS | Windows | 레지스트리 API 의존 (`Microsoft.Win32.Registry`) |
| IDE | 선택 사항 | Visual Studio 2022+ / Rider / VS Code + C# Dev Kit |

솔루션 파일이 **`.slnx` 형식**(새 XML 기반 솔루션 포맷)이라 구버전 도구는 열지 못할 수 있습니다. 그럴 때는 `.csproj`를 직접 열면 됩니다.

## 빌드

```bash
dotnet build "steam game tool.slnx"
```

릴리스 빌드:

```bash
dotnet build "steam game tool.slnx" -c Release
```

## 실행

```bash
dotnet run --project "steam game tool/steam game tool.csproj"
```

빌드 산출물을 직접 실행하려면:

```
steam game tool\bin\Debug\net10.0-windows\steam game tool.exe
```

실행 중인 앱이 있으면 빌드가 산출물 파일을 덮어쓰지 못합니다. 앱을 닫고 다시 빌드하세요.

## 단일 파일로 배포

.NET 없이 도는 exe 하나로 뽑을 때:

```bash
dotnet publish "steam game tool/steam game tool.csproj" -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

산출물 위치: `steam game tool\bin\Release\net10.0-windows\win-x64\publish\`

`IncludeNativeLibrariesForSelfExtract`가 없으면 `av_libglesv2.dll`, `libHarfBuzzSharp.dll`, `libSkiaSharp.dll`이 exe 옆에 따로 생깁니다. 넣으면 exe 하나(약 100MB)만 남습니다. 옆의 `.pdb`는 디버그 기호라 배포할 때 빼도 됩니다 (2026-09-22 확인).

## 권한과 앱이 쓰는 파일

관리자 권한은 필요 없습니다. 레지스트리는 읽기만 합니다. 앱이 쓰는 곳은 아래뿐입니다.

| 위치 | 언제 | 내용 |
|---|---|---|
| `%LOCALAPPDATA%\SteamGameTool\scan-baselines\` | 스캔할 때마다 | 이전 스캔 대비 누락 검사의 기준선 JSON ([10-이름과 내보내기](10-이름과-내보내기.md)) |
| `%LOCALAPPDATA%\SteamGameTool\MelonLoader\` | 「MelonLoader 설치 ▸ 자동 설치…」 | GitHub에서 받은 zip 캐시 |
| 사용자가 고른 폴더 | 「저장」 메뉴 | TXT |
| 게임 폴더 | 확인 창에서 「N개 설치」를 눌렀을 때 | MelonLoader 파일 ([11-MelonLoader 설치](11-MelonLoader-설치.md)) |

게임 폴더에 쓰기 권한이 없으면 그 게임만 「쓰기 권한이 없습니다」로 실패하고 나머지는 계속 설치됩니다.

## 사용 흐름

1. **「폴더 ▸ 자동 감지」를 먼저 눌러 봅니다.** 상태 줄에 찾아낸 `steamapps\common` 경로와 드라이브 최상위의 게임 폴더가 표시됩니다.
   - 아무것도 안 나오면 → 「폴더 ▸ 찾아보기…」로 `common` 폴더를 직접 지정
   - 여러 폴더를 보려면 → 「폴더 ▸ 폴더 추가…」 (입력란에 `;`로 이어집니다)
2. **「스캔 시작」** — 진행 상황이 상태 줄에 게임 이름으로 흐릅니다
3. **「보기」 콤보박스**로 6가지 목록 중 하나를 고릅니다. 「게임만」을 켜 두면 사운드트랙·소프트웨어·도구와 잔여 폴더가 빠집니다
4. **「저장 ▸ TXT로 저장…」** — 지금 보기 목록을 파일 하나로 내보냅니다
5. **「저장 ▸ 6개 모두 저장…」** — 보기 목록 6개를 고른 폴더에 한 번에 저장합니다 (같은 이름 파일은 덮어씀)

**스캔 시간** (2026-09-22, 이 PC, 폴더 968개):

| 상황 | 시간 |
|---|---:|
| 컴퓨터를 켜고 처음 (디스크 캐시가 빈 상태) | 약 98초 |
| 이어서 다시 스캔 | 약 1초 |

처음 스캔은 디스크에서 폴더 목록을 실제로 읽어야 해서 느립니다. 중간에 취소할 방법은 아직 없습니다([07-개선 로드맵](07-개선-로드맵.md) 5번).

## 테스트

```bash
dotnet test "steam game tool.slnx"
```

판별 로직을 건드렸다면 **반드시 돌려 보세요.** xUnit 테스트 163개가 [04-판별 로직](04-판별-로직.md)의 규칙과 MelonLoader 설치 규칙을 고정하고 있습니다. 구성은 [05-코드 레퍼런스](05-코드-레퍼런스.md)「SteamGameTool.Tests」를 보세요.

테스트는 화면을 다루지 않습니다. 저장 파일 수·내용, 보기 항목처럼 사용자에게 보이는 결과는 앱을 실행해서 따로 확인합니다([AGENTS.md](../AGENTS.md)「완료 기준」).

## 개발 도구

Debug 빌드에서만 Avalonia DevTools가 켜집니다 (`Program.BuildAvaloniaApp`의 `WithDeveloperTools()`).

실행 후 **F12**를 누르면 비주얼 트리 검사기가 열립니다. 레이아웃이나 바인딩 문제를 볼 때 씁니다.

Release 빌드에서는 `AvaloniaUI.DiagnosticsSupport` 패키지가 `IncludeAssets=None`으로 빠지므로(`steam game tool.csproj`) 산출물에 포함되지 않습니다.

## 문제 해결

### 빌드가 깨진다

| 증상 | 원인 | 해결 |
|---|---|---|
| `net10.0-windows`를 찾을 수 없음 | .NET 10 SDK 미설치 | `dotnet --list-sdks`로 확인 후 설치 |
| 바인딩 관련 컴파일 에러 | 컴파일드 바인딩이 켜져 있음 | `DataTemplate`에 `x:DataType`이 있는지, 바인딩 경로 오타가 없는지 확인 |
| `AVLN2000 Unable to resolve "Marker.…"` | 보기 항목의 `Tag`에 없는 `Marker` 이름 | `ScanResult.cs`의 `Marker`와 이름을 맞추기 |
| 파일이 다른 프로세스에서 사용 중 | 앱이 실행 중 | 앱을 닫고 다시 빌드 |
| `.slnx`를 못 연다 | 구버전 IDE | `.csproj`를 직접 열기 |

### 실행은 되는데 결과가 이상하다

| 증상 | 확인할 것 |
|---|---|
| 「자동 감지」가 아무것도 못 찾음 | Steam이 설치돼 있는지, 레지스트리 `HKCU\Software\Valve\Steam`에 `SteamPath`가 있는지 |
| 게임이 목록에 안 나옴 | 보기는 **대표 플레이어가 Mono/IL2CPP로 판정된 게임만** 보여 줍니다. 「백엔드 미확정」은 어느 보기에도 없습니다. 「게임만」이 켜져 있으면 비게임도 빠집니다 ([04-판별 로직](04-판별-로직.md)「오탐과 미탐」) |
| 백엔드 판정이 틀린 것 같음 | [04-판별 로직](04-판별-로직.md)「판정을 직접 확인하는 법」으로 대조 |
| 배지가 회색 | 두 곳이 `TagNames` 상수를 공유하므로 일어나지 않아야 합니다. 새 태그를 상수 없이 추가했는지 확인하세요 |
| 스캔이 너무 느림 | 처음 스캔은 오래 걸릴 수 있습니다(위 「스캔 시간」). 다시 스캔해도 느리면 네트워크 드라이브나 느린 외장 디스크를 스캔하고 있는지 확인하세요 |
| 상태 줄에 「⚠ 읽지 못한 항목 N개」 | 권한 문제 등으로 일부 폴더를 열지 못했습니다. 그 게임은 백엔드 미확정이 될 수 있습니다 |
| 「스캔 중 오류가 발생했습니다」 + `Unity classification regression…` 또는 `Existing installation folders disappeared…` | 이전 스캔 대비 누락 검사에 걸렸습니다. 메시지에 나온 폴더를 확인하세요. 풀리지 않으면 [10-이름과 내보내기](10-이름과-내보내기.md)「이전 스캔 대비 누락 검사」 |
| 「저장 실패: Export partition …」 | 목록 분할 검증 실패입니다. 코드 버그이니 그 스캔의 폴더 목록과 함께 보고해 주세요 |
| 「GitHub 에 접속하지 못했습니다」 | 네트워크나 GitHub API 제한(인증 없이 시간당 60회)입니다. 「zip 직접 선택…」으로 설치할 수 있습니다 |
| 「설치 검증 실패: 파일 N개가 없습니다」 | 백신이 파일을 격리했을 가능성이 높습니다. 게임 폴더를 백신 예외에 넣고 다시 시도하세요 |

### Steam 설정을 직접 확인하기

PowerShell에서:

```powershell
(Get-ItemProperty 'HKCU:\Software\Valve\Steam').SteamPath
```

라이브러리 목록을 보려면:

```powershell
$steam = (Get-ItemProperty 'HKCU:\Software\Valve\Steam').SteamPath
Select-String -Path "$steam\steamapps\libraryfolders.vdf" -Pattern '"path"'
```
