# 09. 앱 종류 판별 — 게임과 게임 아닌 것 가르기

> 이 문서는 `steamapps\common` 폴더 중에서 **무엇이 진짜 게임인지** 가려내는 방법을 다룹니다.
> Unity 백엔드 판별은 [04-판별 로직](04-판별-로직.md)의 몫이고, 이 문서는 그 **분모**를 다룹니다.

---

## 왜 필요한가

`steamapps\common` 아래 폴더를 세면 게임 수가 나오지 않습니다. 거기엔 이런 것들이 섞여 있습니다.

| 섞여 있는 것 | 예 |
|---|---|
| 사운드트랙 | `... Original Soundtrack` |
| 소프트웨어 | Blender, Krita, Lossless Scaling |
| 도구·재배포 패키지 | `Steamworks Shared` |
| **설치되어 있지 않은 잔여 폴더** | 게임을 지웠는데 폴더만 남은 것 |

실제 측정 예(2026-09-22, 이 PC의 Steam 라이브러리 2개 + 보존본 게임 폴더 8개):

| | 개수 |
|---|---:|
| 스캔한 폴더 전체 | 968 |
| **게임** (데모 1개, Steam 밖 Unity 게임 8개 포함) | **918** |
| 소프트웨어 | 12 |
| 도구 | 2 |
| 미설치 잔여 폴더 | 36 |

폴더 수를 그대로 "게임 수"라고 부르면 **50개(5.2%)가 부풀려집니다.**

---

## 어디서 정보를 얻나

두 파일을 읽습니다. **둘 다 없어도 도구는 동작합니다** — 정보가 비어 있을 뿐입니다.

### 1. `steamapps\appmanifest_<appid>.acf` — 신원

라이브러리마다 설치된 앱 하나당 하나씩 있는 **텍스트** 파일입니다.

```
"AppState"
{
	"appid"		"1000080"
	"name"		"Zengeon"
	"installdir"	"Zengeon"
}
```

여기서 얻는 것:

| 값 | 쓰임 |
|---|---|
| `appid` | 앱 식별자. `appinfo.vdf`와 이어 주는 열쇠 |
| `name` | **스토어 표기 이름** — 화면에 보여 줄 이름 |
| `installdir` | `common` 아래 폴더 이름 — 스캔한 폴더와 맞춰 보는 열쇠 |

**이 파일이 없는 폴더 = 설치된 앱이 아님**(잔여 폴더). `SteamGame.IsOrphan`이 이것입니다.

폴더명과 스토어명이 다른 경우가 아주 많습니다.

| 폴더명 | 스토어명 |
|---|---|
| `HatinTime` | A Hat in Time |
| `100 Orange Juice` | 100% Orange Juice |
| `ABZU` | ABZÛ |
| `game` | 99 Games: Puzzle, Action, Strategy… |

### 2. `appcache\appinfo.vdf` — 종류

Steam 설치 폴더에 있는 **바이너리** 캐시입니다. 앱마다 `common.type`이 들어 있고, 값은 `Game` / `Demo` / `Application` / `Tool` / `Music` / `Video` / `Config` 등입니다.

> ⚠️ **Valve 의 비공개 포맷입니다.** 문서화된 적이 없고 버전이 올라가면 구조가 바뀝니다.
> 그래서 이 도구의 리더는 **실패를 정상 경로로 취급합니다** — 못 읽으면 빈 결과를 돌려주고, 도구는 종류 구분 없이 그냥 동작합니다.

## `appinfo.vdf` 구조

`SteamCatalog.cs`의 `AppInfoCache`가 읽습니다.

```
┌── 헤더 ────────────────────────────────────┐
│ magic            4바이트                    │  0x07564427 / 28 / 29
│ universe         4바이트                    │
│ 문자열 테이블 오프셋  8바이트 (매직 29 에만)    │
└────────────────────────────────────────────┘
┌── 앱 섹션 (appid 가 0 이면 끝) ─────────────┐
│ appid            4바이트                    │
│ size             4바이트  ← 이후 섹션 길이   │
│ infoState        4바이트  ┐                 │
│ lastUpdated      4바이트  │                 │
│ picsToken        8바이트  │ 고정 헤더        │
│ sha1            20바이트  │ (읽지 않고 건너뜀)│
│ changeNumber     4바이트  │                 │
│ binaryDataSha1  20바이트  ┘ (매직 28 이상)   │
│ 바이너리 KV 트리                            │
└────────────────────────────────────────────┘
┌── 문자열 테이블 (매직 29 에만) ─────────────┐
│ count            4바이트                    │
│ NUL 로 끝나는 문자열 × count                 │
└────────────────────────────────────────────┘
```

### 바이너리 KV 노드

| 값 | 뜻 | 이어지는 것 |
|---|---|---|
| `0x00` | 객체 시작 | 키, 자식들, `0x08` |
| `0x01` | 문자열 | 키, NUL 종료 문자열 |
| `0x02` | int32 | 키, 4바이트 |
| `0x03` `0x04` `0x06` | float / 포인터 / 색 | 키, 4바이트 |
| `0x05` | 와이드 문자열 | 키, NUL 종료 UTF-16 |
| `0x07` `0x0A` | uint64 / int64 | 키, 8바이트 |
| `0x08` | 객체 끝 | — |

**매직 29의 핵심 차이:** 키가 인라인 문자열이 아니라 **문자열 테이블의 uint32 인덱스**입니다. 그래서 파일을 문자열로 훑으면 `type` 같은 키가 안 보입니다.

### 우리가 찾는 값

```
루트
└─ appinfo          ← 래퍼가 한 겹 있다
   └─ common
      └─ type = "Game"
```

`common` **바로 아래**의 `type`만 취합니다(`AppInfoCache.FindType`). 다른 깊이의 `type` 키에 걸리지 않게 하려는 것입니다.

### 실패해도 무너지지 않게

| 상황 | 처리 |
|---|---|
| 파일 없음 | 빈 결과 |
| 모르는 매직 | 빈 결과 (`AppInfoCache.ReadTypes`) |
| 문자열 테이블 개수가 비상식적 | 빈 결과 |
| 파일이 잘림 | 거기까지 읽은 것만 반환 |
| **앱 하나의 KV 가 깨짐** | **그 앱만 건너뛰고 계속** — `size`를 알고 있어서 복구 가능 |
| 중첩 32단계 초과 | 그 앱만 건너뜀 |

## 폴더 → 앱 잇기

`SteamScanner.Scan`이 폴더 이름으로 카탈로그를 찾습니다(`SteamCatalog.Find`, 대소문자 무시).

```
common\Zengeon\          →  installdir "Zengeon"  →  appid 1000080  →  type "Game"
common\LeftoverThing\    →  (없음)                →  잔여 폴더
```

### 한 폴더를 여러 앱이 쓰는 경우

사운드트랙 DLC가 본편과 같은 `installdir`을 갖는 일이 있습니다. 이때 나중에 읽힌 쪽이 이기면 **게임이 사운드트랙으로 둔갑**합니다.

그래서 충돌이 나면 **게임(`Game`/`Demo`)을 대표로 승격**시킵니다(`SteamCatalog.Build`).

### 반대 경우 — 앱은 있는데 폴더가 없음

측정한 라이브러리에서 사운드트랙 18개가 `appmanifest`는 있는데 `common`에 폴더가 없었습니다. DJMAX 계열이 OST를 본편 폴더 안에 넣기 때문입니다.

이 도구는 **폴더를 스캔**하므로 이런 앱은 결과에 나타나지 않습니다. 정상입니다.

## 집계 규칙

`ScanResult.CountedGames`가 기준입니다.

```csharp
HasCatalog ? Games.Where(g => (!g.IsOrphan || g.IsPlayableUnity) && g.IsGameLike) : Games
```

| 조건 | 집계 대상인가 |
|---|---|
| 종류가 `Game` | ✅ |
| 종류가 `Demo` | ✅ — 데모도 게임으로 친다 |
| 종류가 `Unknown` (카탈로그엔 있으나 종류 미상) | ✅ — **모른다고 숨기지 않는다** |
| 종류가 `Music` / `Application` / `Tool` / `Video` / `Config` / `Other` | ❌ |
| `appmanifest` 없음 (잔여 폴더) + Unity 백엔드 없음 | ❌ |
| `appmanifest` 없음 + **Unity 백엔드 감지** | ✅ — Steam 밖에 복사해 둔 게임(보존본)이나 오프라인으로 옮겨 둔 게임 |
| **카탈로그를 아예 못 읽음** | ✅ **전부** — 구분할 근거가 없으므로 |

`IsPlayableUnity`는 `Backend != Unknown`, 곧 플레이어 중 하나라도 Mono나 IL2CPP로 판정된 것입니다. 2026-09-22 실측에서 이렇게 들어온 폴더가 8개였습니다(드라이브 최상위의 보존본 게임 폴더).

마지막 줄이 중요합니다. Steam 이 없거나 파일을 못 읽는 환경에서 **결과가 텅 비면 안 되므로**, 카탈로그가 없으면 예전처럼 모든 폴더를 셉니다. 이때 화면에는 "폴더 N개"로 표시해 게임 수가 아님을 알립니다.

`Unknown`을 게임 쪽에 남기는 것도 같은 원칙입니다 — **확실히 게임이 아닌 것만 배제**합니다.

## 화면에 나오는 것

2026-09-22 이 PC의 실제 화면입니다.

```
게임 918개 — Unity Mono 699 · Unity IL2CPP 133 · MonoBleedingEdge 588 · 구형 레거시(Data/Mono) 110 · 중첩(Unity) 46 · 런타임 미확정 1 · 백엔드 미확정 86
제외: 소프트웨어 12 · 도구 2 · 데모 1 · 미설치 잔여 폴더 36   ·   스캔 폴더: …   ·   ⚠ 읽지 못한 항목 N개 (있을 때만)
```

- **첫 줄**(`BuildSummary`)의 수치는 모두 **집계 대상(`CountedGames`) 기준**입니다. Mono와 IL2CPP는 대표 플레이어 기준이라 서로 겹치지 않고, `Mono = MonoBleedingEdge + 구형 레거시 + 런타임 미확정`입니다(699 = 588 + 110 + 1).
- **둘째 줄**(`BuildStatus`)은 무엇을 뺐는지, 어느 폴더를 스캔했는지, 경고가 있는지를 적습니다. 「사운드트랙」「영상」은 있을 때만 나옵니다.
- `appinfo.vdf`를 못 읽으면 첫 줄이 「게임 N개」 대신 「폴더 N개」로 바뀌고, 둘째 줄에 「Steam 앱 목록을 읽지 못해 종류를 구분하지 못했습니다」가 나옵니다.

> ⚠️ 둘째 줄의 「데모」는 제외된 것이 아닙니다. 데모는 게임으로 세므로 918 안에 들어 있습니다(918 + 12 + 2 + 36 = 968). `Config`·`Other` 종류는 게임에서 빠지지만 둘째 줄에 나오지 않습니다. [07-개선 로드맵](07-개선-로드맵.md) 13번.

「**게임만**」 체크박스(기본 켜짐)로 목록에서도 비게임을 숨길 수 있습니다. 카탈로그가 없으면 이 체크박스는 무시됩니다.

## Steam 라이브러리 화면의 숫자와 다른 이유

Steam 의 필터 패널이 보여 주는 `게임(852) / 사운드트랙(31) / 소프트웨어(18) / 도구(132)`는 **보유(owned) 기준**입니다. 이 도구는 **설치되어 디스크에 폴더가 있는 것**만 셉니다.

| | Steam 필터 패널 | 이 도구 |
|---|---|---|
| 기준 | 라이브러리에 보유 중 | 디스크에 설치됨 |
| 사운드트랙 | 구매한 전부 | 별도 폴더로 설치된 것만 |
| 도구 | 보유한 전부 | 설치된 것만 |

**두 숫자는 원래 일치하지 않습니다.**

## 관련 코드

| 위치 | 역할 |
|---|---|
| `SteamAppType` | 앱 종류 열거형 (`SteamCatalog.cs`) |
| `SteamCatalog` | 폴더명 → 앱 |
| `SteamCatalog.Build` | acf + appinfo 읽어 조립 |
| `SteamCatalog.AcfValue` | 텍스트 VDF 값 추출 |
| `AppInfoCache` | 바이너리 리더 |
| `SteamLibraries.LibraryRootOf` | common → 라이브러리 루트 |
| `SteamScanner.Scan` | 폴더와 카탈로그 잇기 |
| `SteamGame.IsGameLike`, `ScanResult.CountedGames` | 게임으로 볼 것, 집계 대상 |
| `MainWindow.BuildSummary`, `BuildStatus` | 요약·상태 줄 |

테스트는 `SteamGameTool.Tests/CatalogTests.cs`(합성 `appinfo.vdf` 포함)와 `AppTypeScanTests.cs`에 있습니다.
