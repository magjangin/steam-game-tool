## Unity 관련

### 스크립팅 백엔드 (Scripting Backend)
Unity가 C# 코드를 실행 가능한 형태로 만드는 방식. **Mono**와 **IL2CPP** 두 가지가 있고, 이 도구가 판별하는 대상입니다.

### Mono
C# 코드를 IL이 담긴 `.dll`로 배포하고, 실행 시점에 Mono 런타임이 기계어로 변환(JIT)하는 방식. 코드가 사실상 원형 그대로 남아 있어 **읽고 고치기 쉽습니다.**

### IL2CPP (Intermediate Language To C++)
IL을 C++ 소스로 변환한 뒤 네이티브 기계어로 컴파일하는 방식. 결과물이 `GameAssembly.dll`이며, 관리 코드가 남지 않아 **분석과 수정이 어렵습니다.**

### IL (Intermediate Language)
.NET의 중간 언어. C# 컴파일러의 1차 출력물이며, CPU가 직접 실행하지는 못합니다. **Mono든 IL2CPP든 일단 여기까지는 똑같이 거칩니다.** 차이는 그다음에 갈립니다.

### JIT / AOT
**JIT**(Just-In-Time)는 실행 중에 기계어로 변환 — Mono가 이 방식. **AOT**(Ahead-Of-Time)는 미리 변환해 두는 것 — IL2CPP가 이 방식.

### `<게임>_Data` 폴더
Unity 스탠드얼론 빌드가 실행 파일 옆에 만드는 폴더. 이름이 **실행 파일명 + `_Data`**입니다. 에셋·설정·코드가 여기 들어갑니다. **이 도구의 모든 판별이 이 폴더를 기준점으로 시작합니다.**

### `Managed` 폴더
`<게임>_Data\Managed\`. Mono 빌드에서 .NET 어셈블리(`.dll`)들이 놓이는 곳. IL2CPP 빌드에는 보통 없습니다.

### `Assembly-CSharp.dll`
게임 개발자가 직접 작성한 C# 코드가 전부 들어 있는 어셈블리. Unity가 자동으로 이 이름을 붙입니다. **이 파일이 있으면 Mono 빌드가 거의 확실합니다.**

### `Assembly-CSharp-firstpass.dll`
`Plugins`나 `Standard Assets` 폴더 아래의 코드가 들어가는 별도 어셈블리. 이름대로 **먼저 컴파일**되어 `Assembly-CSharp`이 참조할 수 있습니다.

### `UnityEngine.dll` / `UnityEngine.CoreModule.dll`
Unity 엔진 API의 관리 코드 래퍼. Unity 2017.2에서 엔진이 모듈 단위로 쪼개지면서 통짜 `UnityEngine.dll`이 `UnityEngine.CoreModule.dll` 등 여러 개로 나뉘었습니다. **이 도구는 둘 다 확인합니다.**

### MonoBleedingEdge
Unity가 자체 포크해 쓰는 Mono 런타임, 그리고 그것이 담긴 폴더 이름. "Bleeding Edge"는 당시 Mono 최신 브랜치에서 갈라져 나왔다는 뜻입니다. 보통 실행 파일 옆(게임 폴더 최상위)에 있고, `<게임>_Data\` 안에 있는 게임도 있습니다. **구버전 Unity는 대신 `<게임>_Data\Mono\`를 씁니다.** 이 도구는 이 둘로 보기 「MonoBleedingEdge」와 「Mono (구형 레거시)」를 가릅니다.

### `GameAssembly.dll`
IL2CPP가 만들어 내는 네이티브 DLL. 게임의 C# 코드가 C++을 거쳐 기계어로 변환된 결과가 전부 여기 들어 있습니다. **IL2CPP 빌드에만 존재합니다.**

### `global-metadata.dat`
`<게임>_Data\il2cpp_data\Metadata\`에 있는 파일. IL2CPP가 네이티브 변환 과정에서 떼어 낸 타입·메서드·문자열 이름 등의 메타데이터입니다. **IL2CPP 빌드에만 존재하며, 이 도구가 쓰는 가장 확실한 판별 근거입니다.**

### `UnityPlayer.dll`
Unity 엔진의 네이티브 코어. **Mono와 IL2CPP 양쪽 모두에 존재**하므로 이것만으로는 백엔드를 구분할 수 없습니다. 이 도구는 `GameAssembly.dll`과 **함께** 있을 때만 IL2CPP 근거로 씁니다([04-판별 로직](04-판별-로직.md) 규칙 2-B).

## Steam 관련

### 라이브러리 (Library Folder)
Steam이 게임을 설치하는 최상위 폴더. **여러 개일 수 있습니다** — C드라이브가 차서 D나 H드라이브에 추가하는 게 흔합니다. 각 라이브러리 아래에 `steamapps\`가 있습니다.

### `steamapps\common`
실제 게임 파일이 게임별 폴더로 들어가는 곳. **이 도구가 스캔하는 대상**입니다.

### `libraryfolders.vdf`
`<steam>\steamapps\`에 있는 파일. **모든 라이브러리 폴더의 경로 목록**이 들어 있습니다. 이 도구가 여러 드라이브의 게임을 찾아내는 방법입니다.

### `appmanifest_<appid>.acf`
`steamapps\`에 설치된 앱마다 하나씩 있는 파일. AppID, 스토어 표기 이름, 설치 폴더명, 설치 상태 등이 들어 있습니다. **이 도구가 게임 이름과 신원을 얻는 곳**이며, 이 파일이 없는 `common` 폴더는 설치된 앱이 아니라 잔여 폴더로 봅니다 ([09-앱 종류 판별](09-앱-종류-판별.md)).

### VDF (Valve Data Format)
Valve의 키-값 텍스트 형식. JSON과 비슷하지만 콜론과 쉼표가 없습니다.

```
"AppState"
{
    "appid"  "367520"
    "name"   "Hollow Knight"
}
```

`libraryfolders.vdf`와 `.acf` 파일이 이 형식입니다.

### AppID
Steam이 게임마다 붙이는 고유 번호. `steam://run/<appid>`로 실행하거나 스토어 URL에 씁니다. `appmanifest`와 `appinfo.vdf`를 잇는 열쇠입니다.

### `appinfo.vdf`
Steam 설치 폴더의 `appcache\`에 있는 **바이너리** 캐시. 앱마다 `common.type`(Game/Music/Tool/Application 등)이 들어 있어, 이 도구가 게임과 사운드트랙·소프트웨어를 구분하는 근거가 됩니다. **Valve의 비공개 포맷**이라 언제든 바뀔 수 있어, 읽지 못하면 종류 없이 동작하도록 되어 있습니다 ([09-앱 종류 판별](09-앱-종류-판별.md)).

### 잔여 폴더 (orphan)
`steamapps\common`에 폴더는 있는데 대응하는 `appmanifest`가 없는 것. 게임을 지웠는데 폴더만 남은 경우가 대부분입니다. 이 도구는 게임 수에서 제외하고 따로 셉니다. 단, Unity 백엔드가 감지된 폴더(Steam 밖에서 복사해 둔 게임 등)는 게임으로 칩니다.

## 모딩 / 분석 도구

### BepInEx
Unity 게임용 모드 로더 중 가장 널리 쓰입니다. **Mono용과 IL2CPP용 빌드가 따로 있어서**, 잘못 받으면 동작하지 않습니다. 이 도구가 필요한 주된 이유 중 하나입니다.

### MelonLoader
Unity 게임용 모드 로더. Mono와 IL2CPP를 모두 지원합니다. 게임 폴더에 `version.dll`(프록시)과 `MelonLoader\`를 넣어 동작합니다. 이 도구는 체크한 게임에 한 번에 설치할 수 있습니다([11-MelonLoader 설치](11-MelonLoader-설치.md)).

### CI 빌드 (nightly)
MelonLoader GitHub에서 정식 릴리스 사이에 자동으로 나오는 시험판. 로그에는 `v0.7.3-ci.2497`처럼, DLL 버전에는 네 번째 자리가 빌드 번호(`0.7.3.2497`)로 찍힙니다. 이 도구는 같은 번호의 정식 릴리스보다 **낮은** 버전으로 봅니다.

### dnSpy / ILSpy
.NET 어셈블리 디컴파일러. **Mono 빌드의 `Assembly-CSharp.dll`을 열면 C# 소스에 가까운 코드를 볼 수 있습니다.** dnSpy는 수정 후 저장까지 됩니다.

### Il2CppDumper
`GameAssembly.dll`과 `global-metadata.dat`을 대조해 IL2CPP 게임의 타입·메서드 구조를 복원하는 도구. 완전한 소스 복원은 아니고 **구조 정보 수준**입니다.

## 이 도구의 용어

### 플레이어
`*_Data` 폴더 하나와 그 옆의 실행 파일. Unity 게임 하나의 실행 단위입니다. 한 게임 폴더에 여러 개 있을 수 있습니다(런처와 본편, 64비트와 32비트 등).

### 대표 플레이어 / 선택 신뢰도
플레이어가 여럿일 때 목록 분류에 쓰려고 고른 하나. 이름·실행 파일·크기 순으로 고르고, 어떻게 골랐는지에 따라 신뢰도가 high / medium / low로 붙습니다. low는 MelonLoader 자동 설치에서 건너뜁니다([04-판별 로직](04-판별-로직.md)「대표 플레이어 고르기」).

### 구형 레거시 Mono
대표 플레이어가 Mono이고 런타임이 `MonoBleedingEdge\`가 아니라 `Mono\`(옛 Unity)인 게임. MelonLoader 자동 설치 대상이 아닙니다.

### 런타임 미확정 / 백엔드 미확정
**런타임 미확정**은 Mono인 것은 확실한데 Mono 런타임 폴더를 못 찾은 게임입니다. **백엔드 미확정**은 대표 플레이어를 정하지 못한 항목으로, Unity가 아닌 게임과 Unity 근거는 있지만 판정하지 못한 게임이 섞여 있습니다. 「Unity가 아니다」라는 뜻이 아닙니다.

### nameKey
화면 이름을 정규화한 값(NFC, 공백·아포스트로피 정리). 정렬과 TXT 내보내기에 씁니다. 화면에는 원래 이름이 나옵니다([10-이름과 내보내기](10-이름과-내보내기.md)).

### 보존본 게임 폴더
Steam 라이브러리 밖(예: 드라이브 최상위)에 따로 둔 Unity 게임 폴더. 자동 감지가 드라이브 최상위에서 찾고, 폴더 하나를 게임 하나로 스캔합니다.

### 스캔 기준선
이전 스캔 결과를 기억해 두는 파일(`%LOCALAPPDATA%\SteamGameTool\scan-baselines\`). 게임이 목록에서 조용히 사라지는 것을 막는 검사에 씁니다([10-이름과 내보내기](10-이름과-내보내기.md)「이전 스캔 대비 누락 검사」).

## .NET / 코드 관련

### `[Flags]` 열거형
비트 조합으로 쓰는 열거형. 값을 `|`로 합치고 `&`로 검사합니다. 이 프로젝트의 `UnityBackend`가 그렇습니다 — **Mono와 IL2CPP가 동시에 참일 수 있어야** 하기 때문입니다.

### 컴파일드 바인딩 (Compiled Bindings)
Avalonia가 XAML 바인딩을 **컴파일 타임에 검증**하는 기능. 오타가 나면 런타임에 조용히 실패하는 대신 빌드가 깨집니다. 대신 `DataTemplate`에 `x:DataType` 명시가 필요합니다. 이 프로젝트는 `AvaloniaUseCompiledBindingsByDefault`로 켜 두었습니다.

### `ObservableCollection<T>`
항목이 추가·제거되면 UI에 자동으로 알리는 컬렉션. `MainWindow._view`가 이것이라 `ListBox`가 따라 갱신됩니다. **다만 항목 내부 프로퍼티 변경까지 알려 주지는 않습니다** — 그건 `INotifyPropertyChanged`의 몫입니다. `SteamGame`은 이것을 구현하지만 `InstallChecked`(설치 대상 체크)만 알립니다.

### `Dispatcher.UIThread.Post`
백그라운드 스레드에서 UI 스레드로 작업을 넘기는 Avalonia API. Avalonia 컨트롤은 UI 스레드에서만 접근할 수 있습니다.

### `async void`
반환값이 없는 비동기 메서드. **이벤트 핸들러에서만 써야 합니다.** 예외가 밖으로 새어 나가면 `await`으로 받을 곳이 없어 프로세스가 죽을 수 있으므로, **핸들러가 스스로 try/catch를 해야 합니다.**

### `required init`
C# 11+ 문법. `required`는 객체 초기화 시 반드시 값을 줘야 함을, `init`은 그 이후 변경할 수 없음을 뜻합니다. `SteamGame.Name`과 `InstallDir`이 이렇습니다.

### 리파스 포인트 (Reparse Point)
심볼릭 링크·정션 등 다른 경로를 가리키는 특수 디렉터리 항목. 재귀 순회에서 걸러 내지 않으면 **무한 루프에 빠질 수 있어서**, 이 도구는 `*_Data`를 찾을 때 그 아래로 내려가지 않습니다(`UnityInspector.Walk`). 대표 플레이어를 크기로 고를 때도 건너뜁니다(`GameClassification.Select`).

### `.slnx`
Visual Studio의 새 XML 기반 솔루션 파일 형식. 기존 `.sln`의 텍스트 형식을 대체합니다. **구버전 도구는 열지 못할 수 있습니다.**
