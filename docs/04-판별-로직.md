# 04. 판별 로직

> 게임 폴더 하나를 보고 **Unity인지, 어떤 백엔드인지** 정하는 규칙 전문입니다. 코드는 `UnityInspector`(폴더 훑기·플레이어별 판정)와 `GameClassification`(대표 플레이어 고르기)에 있습니다.
> 판별 규칙을 바꾸면 이 문서와 `SteamGameTool.Tests/BackendDetectionTests.cs`를 함께 고칩니다.
> 게임과 사운드트랙·도구를 가르는 규칙은 [09-앱 종류 판별](09-앱-종류-판별.md), 목록과 TXT 형식은 [10-이름과 내보내기](10-이름과-내보내기.md)에 있습니다.

판별은 세 단계입니다.

1. **폴더 훑기** — 설치 폴더 아래를 한 번 훑어 `*_Data` 폴더, `Managed`, `MonoBleedingEdge`를 모읍니다.
2. **플레이어별 판정** — `*_Data` 하나를 플레이어 하나로 보고 Mono / IL2CPP / 모름을 정합니다. 결과는 게임마다 `BackendEvidence` 목록으로 남습니다.
3. **대표 플레이어 고르기** — 플레이어가 여럿이면 하나를 골라 목록 분류에 씁니다. 고른 이유와 신뢰도도 남깁니다.

---

## 1. 폴더 훑기 — `UnityInspector.Walk`

설치 폴더에서 시작해 하위 폴더를 **한 번만** 훑습니다. 파일은 열지 않고 이름과 존재 여부만 봅니다.

| 항목 | 규칙 |
|---|---|
| 깊이 | 설치 폴더 기준 8단계까지 (`MaxScanDepth`). 아래 「깊이 상한」 참고 |
| 건너뛰는 폴더 | 이름에 `MelonLoader`, `BepInEx`, `Voice Editor`, `Modded`, `BackUpThisFolder`, `__MACOSX`가 들어가거나(대소문자 무시) `.app`으로 끝나는 폴더. 그 아래로도 내려가지 않습니다 |
| `Managed` | 어느 깊이든 이 이름의 폴더가 있으면 `HasManaged` (배지 「Managed」) |
| `MonoBleedingEdge` | 어느 깊이든 이 이름의 폴더가 있으면 `HasMonoBleedingEdge` (배지 「MonoBleedingEdge」). 위치는 런타임 후보로도 남깁니다 |
| `*_Data` 후보 | 이름이 `_Data`로 끝나는 폴더(대소문자 무시). 단, 아래 「데이터 후보에서 빼는 곳」에 해당하지 않아야 합니다 |

**데이터 후보에서 빼는 곳.** `*_Data`는 아래 위치에서는 찾지 않습니다. 보조 마커(`Managed`·`MonoBleedingEdge`)는 여기서도 계속 찾습니다.

- `Managed`, `MonoBleedingEdge`, `Mono` 폴더의 아래
- `il2cpp_data` 폴더와 그 아래
- 재분석 지점(정션·심볼릭 링크)과 그 아래 — 순환을 막기 위해서입니다

**폴더를 읽지 못하면.** 데이터 후보를 찾던 경로에서 폴더 목록을 읽지 못하면(권한 거부 등) 그 게임의 **데이터 근거 전체를 버립니다.** 일부만 읽은 결과로 판정하지 않기 위해서입니다. 이때 백엔드는 「모름」이 되고 오류는 `ScanResult.Warnings`에 남아 상태 줄에 「⚠ 읽지 못한 항목 N개」로 나옵니다. 보조 마커는 읽은 만큼 남깁니다.

## 2. 플레이어별 판정 — `UnityInspector.AddPlayerEvidence`

`*_Data` 폴더 하나 = 플레이어 하나입니다. 플레이어 폴더는 `*_Data`의 부모 폴더입니다.

### 판정 요약표

위에서부터 먼저 맞는 규칙 하나로 정합니다. 번호는 `BackendDetectionTests.cs`의 주석과 같습니다.

| 규칙 | 조건 (한 플레이어 안에서) | 판정 | `Rule` 값 |
|---|---|---|---|
| 2-A | `<이름>_Data\il2cpp_data\Metadata\global-metadata.dat`가 있음 | **IL2CPP** | `global-metadata.dat` |
| 2-B | 플레이어 폴더에 `GameAssembly.dll`과 `UnityPlayer.dll`이 **둘 다** 있음 | **IL2CPP** | `native-player-pair` |
| 1-B | `<이름>_Data\Managed\`에 `Assembly-CSharp.dll`, `Assembly-CSharp-firstpass.dll`, `UnityEngine.dll`, `UnityEngine.CoreModule.dll` 중 하나가 있음 | **Mono** | `managed-assembly` |
| 1-C | `Managed` 폴더가 있고, Mono 런타임 폴더(아래 표)도 있음 | **Mono** | `runtime-and-managed` |
| — | 위 어디에도 맞지 않음 | 모름 | `unknown` |
| 1-A | `*_Data` 없이 `MonoBleedingEdge\`만 있는 위치 | **Mono** | `monobleedingedge-runtime` |

- **IL2CPP가 먼저입니다.** 단, 그 우선순위는 **한 플레이어 안에서만** 적용합니다. 다른 플레이어의 IL2CPP 증거가 이 플레이어의 Mono 판정을 덮지 않습니다.
- **`UnityPlayer.dll` 하나, `GameAssembly.dll` 하나, 빈 `Managed` 폴더 하나로는 판정하지 않습니다.** 셋 다 테스트가 고정하고 있습니다.
- **규칙 1-A**는 `*_Data`를 찾지 못한 곳에 `MonoBleedingEdge\`만 있을 때의 폴백입니다. 이미 플레이어로 기록한 폴더이거나 그 플레이어의 런타임으로 기록한 경로면 다시 기록하지 않습니다.

### 런타임

Mono 플레이어는 런타임 폴더도 기록합니다. 이것이 보기 「MonoBleedingEdge」와 「Mono (구형 레거시)」를 가릅니다.

| 런타임 | 찾는 곳 (앞에서부터) | `Runtime` 값 |
|---|---|---|
| MonoBleedingEdge (최근 Unity) | `<플레이어>\MonoBleedingEdge\` → `<이름>_Data\MonoBleedingEdge\` | `monobleedingedge` |
| 구형 Mono (옛 Unity) | `<이름>_Data\Mono\` → `<플레이어>\Mono\` | `mono` |
| 둘 다 없음 | — | `null` (런타임 미확정) |

IL2CPP 플레이어의 `Runtime`은 `il2cpp`입니다. `Data\Mono\EmbedRuntime`, `Data\Mono\x86_64` 같은 하위 구조는 부모 `Mono\` 폴더로 잡힙니다.

### 함께 기록하는 것

| 값 | 뜻 |
|---|---|
| `DataPath` | 설치 폴더 기준 `*_Data` 상대 경로. 규칙 1-A는 `null` |
| `PlayerPath` | 플레이어 폴더 상대 경로 (`.`은 설치 폴더 자체) |
| `Layer` | `*_Data`가 설치 폴더 바로 아래면 `outer`, 더 깊으면 `inner`. **위치일 뿐** 런처·본편 역할을 뜻하지 않습니다 |
| `ExecutablePath` / `ExecutableSize` | `*_Data` 옆의 `<이름>.exe`. 없으면 `null` / 0 |
| `IsBundled` | 경로에 `_anniversary` 폴더가 있음. 함께 담겨 배포된 별도 빌드라는 표시입니다 |
| `HasManaged` | 이 플레이어의 `Managed\` 폴더 존재 |

### 게임 단위로 합치기

- **`Backend`** (배지 「Unity Mono」·「Unity IL2CPP」)는 모든 플레이어 판정의 **합집합**입니다. 런처는 Mono, 본편은 IL2CPP이면 배지가 둘 다 붙습니다.
- **목록 분류**(보기 6개, TXT)는 합집합이 아니라 아래 「대표 플레이어」 하나의 판정을 씁니다. 그래서 한 게임은 보기 「Unity Mono」와 「Unity IL2CPP」 중 하나에만 나옵니다.

## 3. 대표 플레이어 고르기 — `GameClassification.Select`

후보는 **백엔드가 정해진 플레이어**입니다. `*_Data`가 있는 후보가 하나라도 있으면 규칙 1-A(런타임만 있는 위치)는 후보에서 뺍니다.

| 상황 | 고르는 방법 | `Reason` | 신뢰도 |
|---|---|---|---|
| 후보 없음 | — (백엔드 미확정) | `no-backend-evidence` | low |
| 후보 하나 | 그것 | `single-player` | high (번들이면 low) |
| 여럿 | 아래 단계를 차례로. 한 단계에서 맞는 후보가 **하나**면 그것으로 끝, 여럿이면 그들로 좁혀 다음 단계, 없으면 좁히지 않고 다음 단계 | 단계 이름 | medium (번들이면 low) |
| 여전히 여럿 | 데이터 폴더 전체 크기가 가장 큰 것 (동률이 아닐 때만) | `largest-data-folder` | low |
| 크기도 동률 | `outer` 먼저, 그다음 경로 순서 | `outer-then-path-tiebreak` | low |

좁히는 단계:

1. `exact-install-name` — `<이름>_Data`의 이름이 설치 폴더 이름과 같음
2. `normalized-install-name` — 이름을 정규화(글자·숫자만, 대문자)하면 같음. 예: `Chrono Ark` ↔ `ChronoArk_Data`
3. `prefix-install-name` — 정규화한 이름의 한쪽이 다른 쪽으로 시작함. 예: `TerraTech` ↔ `TerraTechWin64_Data`
4. `matched-player-executable` — `<이름>.exe`가 있음
5. `player-data-evidence` — `Managed\`가 있거나 `global-metadata.dat`로 판정됨

게임 단위 값은 대표 플레이어에서 나옵니다.

| 값 | 조건 | 쓰는 곳 |
|---|---|---|
| `ClassifiedBackend` | 대표 플레이어의 백엔드 (없으면 Unknown) | 보기 「Unity Mono」·「Unity IL2CPP」 |
| `IsBackendUnresolved` | 대표 플레이어 없음 | 요약 「백엔드 미확정」 |
| `HasModernMono` | Mono이고 런타임이 `monobleedingedge` | 보기 「MonoBleedingEdge」 |
| `HasLegacyMono` | Mono이고 런타임이 `mono` | 보기 「Mono (구형 레거시)」 |
| `IsRuntimeUnresolved` | Mono이고 런타임을 못 찾음 | 요약 「런타임 미확정」 |
| `HasNestedUnity` | 백엔드가 정해진 플레이어 중 `inner`가 하나라도 있음 (대표 여부와 무관) | 보기 「중첩」 |
| `HasNestedMatch` | 설치 폴더 안에 같은 이름의 하위 폴더가 있음 (`Foo\Foo\`) | 배지 「중첩」 |

**전체 스캔은 빠짐없이 한 칸에 들어갑니다.** Mono / IL2CPP / 백엔드 미확정이 서로 겹치지 않고, Mono는 다시 구형 레거시 / MonoBleedingEdge / 런타임 미확정으로 나뉩니다. 저장할 때 `ExportLists`가 이것을 실제 목록으로 확인하고, 어긋나면 저장하지 않습니다([10-이름과 내보내기](10-이름과-내보내기.md)).

> 배지 「중첩」과 보기 「중첩」은 기준이 다릅니다. 배지는 같은 이름 하위 폴더(`HasNestedMatch`), 보기는 하위 폴더에 Unity 플레이어가 있는가(`HasNestedUnity`)입니다. 예를 들어 Jaded는 `Jaded\Jaded\` 폴더가 있어 배지는 붙지만, 플레이어가 설치 폴더 바로 아래에 있어 보기에는 나오지 않습니다.

## 깊이 상한

`MaxScanDepth = 8`은 스캔 속도를 좌우하는 값입니다. 제한 없이 훑던 시절에는 게임 885개 스캔에 137.6초가 걸렸습니다([07-개선 로드맵](07-개선-로드맵.md) 1번).

2026-09-22 실측(폴더 968개): 판정에 쓰인 `*_Data`의 깊이 분포입니다(`Foo_Data` = 1, `bin\Foo_Data` = 2).

| 깊이 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 개수 | 808 | 44 | 5 | 1 | 3 | 8 | 2 | 1 |

- 대표 플레이어 중 가장 깊은 것은 CUSTOM ORDER MAID 3D2 It's a Night Magic의 `com3d2inm\dlc\enpublic\inm_update\inm_update\data\COM3D2x64_Data`(깊이 7)입니다.
- 깊이 7·8의 나머지는 플레이어가 아닌 폴더입니다(아래 「오탐과 미탐」의 `_data` 이름). 대표로 뽑히지는 않았습니다.
- 상한을 줄이면 판별 결과가 바뀔 수 있습니다. 바꾸기 전에 실제 라이브러리로 전후 결과를 대조하세요.

## 오탐과 미탐

도구가 틀리거나 판단을 보류하는 경우입니다. 실제로 확인된 사례만 적었습니다.

| 경우 | 결과 | 사례 |
|---|---|---|
| Unity가 아닌 엔진 (Unreal, Godot, RPG 쯔꾸르 등) | 백엔드 미확정. 엔진을 판정하지는 않습니다 | — |
| Unity가 **런처에만** 쓰인 게임 | 런처의 백엔드로 분류됩니다 | LiEat: `LiEat_Launcher.exe`(Unity 5.4)만 Unity이고 본편은 WOLF RPG 에디터 게임이라 「구형 레거시」로 나옵니다 |
| DLC·업데이트 데이터가 더 큰 게임 | 크기 폴백이 엉뚱한 폴더를 대표로 고릅니다(신뢰도 low) | The Long Dark → `tld_dlc\wintermute\tld_Data`, CUSTOM ORDER MAID 3D2 → `dlc\...\COM3D2x64_Data` |
| 실행 파일이 `*_Data` 옆에 없는 게임 | 분류는 되지만 `ExecutablePath`가 비어 MelonLoader 설치에서 건너뜁니다 | Chrono Ark: exe가 `x64\Master\`에 따로 있음 |
| 이름이 `_data`로 끝나는 일반 폴더 | 데이터 후보가 되지만 근거가 없어 「모름」으로 남습니다 | LiveMate의 `...\librosa\util\example_data`, Poetry of Blood: Eclipse의 `...\assets\_data` |
| 번들 빌드 (`_anniversary`) | 판정은 하되 신뢰도 low | Edna & Harvey: The Breakout |
| 건너뛰는 이름이 든 폴더 | 판정에서 빠집니다. 모드 로더·백업 폴더 오염을 막기 위한 대가입니다 | 이름에 `Modded`가 든 플레이어 폴더 등 |
| 깊이 8 아래의 플레이어 | 보지 못합니다 | 2026-09-22 실측에서는 없음 |
| 읽지 못한 폴더가 있는 게임 | 데이터 근거를 통째로 버려 백엔드 미확정 + 경고 | — |

2026-09-22 실측에서 대표 플레이어 신뢰도는 high 819 · medium 8 · low 5였습니다. low 5개는 위 표의 The Long Dark, CUSTOM ORDER MAID 3D2, Edna & Harvey와 Diorama Builder, Journey of a Roach입니다.

## 판정을 직접 확인하는 법

도구의 판정이 의심스러우면 게임 폴더를 직접 봅니다. PowerShell 예시입니다.

```powershell
$game = "H:\steam\steamapps\common\Hollow Knight"   # 확인할 게임 폴더

# 1) 플레이어 찾기: *_Data 폴더
Get-ChildItem $game -Recurse -Depth 7 -Directory -Filter *_Data | Select-Object FullName

# 2) 각 *_Data 에 대해 (예: hollow_knight_Data)
$data = Join-Path $game "hollow_knight_Data"
$player = Split-Path $data
Test-Path "$data\il2cpp_data\Metadata\global-metadata.dat"                              # True → IL2CPP (2-A)
(Test-Path "$player\GameAssembly.dll") -and (Test-Path "$player\UnityPlayer.dll")       # True → IL2CPP (2-B)
Get-ChildItem "$data\Managed" -Filter "Assembly-CSharp*.dll" -ErrorAction SilentlyContinue  # 있으면 Mono (1-B)

# 3) Mono 런타임
Test-Path "$player\MonoBleedingEdge", "$data\MonoBleedingEdge"   # 하나라도 True → MonoBleedingEdge
Test-Path "$data\Mono", "$player\Mono"                           # 하나라도 True → 구형 레거시
```

여러 플레이어가 나오면 위 「대표 플레이어 고르기」 순서로 어느 것이 대표인지 따져 봅니다.
