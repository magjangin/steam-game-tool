# 03. 아키텍처

## 전체 구조

소스 7개짜리 소규모 프로젝트입니다. MVVM이나 DI 컨테이너 없이, **UI 계층이 스캐너 계층을 직접 호출**하는 2층 구조입니다.
별도 테스트 프로젝트(`SteamGameTool.Tests`)가 스캐너 계층을 직접 검증합니다.

### 계층 규칙

- **스캐너 계층은 UI를 전혀 모릅니다.** Avalonia 타입을 참조하지 않고, 전부 `static` 함수입니다. 그래서 콘솔 앱이나 테스트에서 그대로 호출할 수 있습니다.
- **UI 계층은 상태를 두 벌 들고 있습니다.** `_last`는 스캔 결과 전체, `_view`는 현재 필터를 통과한 부분집합입니다. 필터를 바꿔도 **재스캔하지 않고** `_last`에서 다시 걸러 냅니다 (`MainWindow.axaml.cs:221`).
- **ViewModel이 없습니다.** 이 규모에서는 과합니다. 다만 기능이 늘어나면 `MainWindow.axaml.cs`가 먼저 비대해집니다.

## 스레딩 모델

| 작업 | 스레드 | 근거 |
|---|---|---|
| 스캔 전체 | 백그라운드 (`Task.Run`) | UI를 막으면 안 됨 |
| 게임 폴더 검사 | **워커 스레드 여러 개** (`Parallel.ForEach`) | 폴더끼리 독립적이고 I/O 바운드 |
| 진행 상황 보고 | UI (`Dispatcher.UIThread.Post`) | Avalonia 컨트롤은 UI 스레드에서만 접근 가능 |
| 필터 적용 | UI (동기) | 메모리 안의 리스트 필터링이라 즉시 끝남 |
| 파일 저장 | UI (`async`, I/O는 비동기) | `await`로 넘겨서 UI가 안 막힘 |

### 병렬 스캔의 계약

`Scan()`은 게임 폴더를 `Parallel.ForEach`로 처리합니다 (`SteamScanner.cs:283`). 여기서 나오는 제약입니다.

- **`progress` 콜백이 여러 스레드에서 동시에 호출됩니다.** 호출자가 스레드 안전해야 합니다. UI 코드는 `Dispatcher.UIThread.Post`를 쓰므로 안전합니다 (`MainWindow.axaml.cs:48`).
- **`ScanResult.Games`·`Warnings` 추가는 `lock`으로 보호됩니다** (`SteamScanner.cs:320`).
- **결과 순서는 결정적입니다.** 병렬로 모은 뒤 마지막에 이름순 정렬하기 때문입니다 (`SteamScanner.cs:329`). 실제 라이브러리에서 3회 반복 실행해 동일 결과를 확인했습니다.

### 알아 둘 것

- **`progress` 콜백은 게임 폴더 하나마다 `Post`를 한 번씩 날립니다.** 게임이 900개면 `Post`가 900번입니다 (`MainWindow.axaml.cs:48`). 스캔이 1초 이내로 끝나는 지금은 문제가 아니지만 스로틀링 여지는 남아 있습니다.
- **취소 수단이 없습니다.** `CancellationToken`을 받지 않아서, 스캔이 시작되면 끝날 때까지 기다려야 합니다 ([07-개선 로드맵](07-개선-로드맵.md) 5번).
- **`async void` 핸들러 3개**(`OnScanClick`, `OnBrowseClick`, `OnExportClick`)는 이벤트 핸들러라 불가피합니다. `async void`에서 예외가 새어 나가면 프로세스가 죽으므로 **각 핸들러가 스스로 try/catch를 합니다.** 현재 셋 다 갖추고 있습니다.

## 바인딩 구조

`AvaloniaUseCompiledBindingsByDefault`가 켜져 있어서(`steam game tool.csproj`) 바인딩이 **컴파일 타임에 검증**됩니다. 오타가 나면 런타임에 조용히 실패하는 대신 빌드가 깨집니다.

그래서 `DataTemplate`마다 `x:DataType`이 필수입니다.

```
ListBox.ItemsSource = _view                        (코드에서 직접 설정)
  └─ DataTemplate  x:DataType="local:SteamGame"
       ├─ TextBlock ← {Binding Name}
       ├─ TextBlock ← {Binding InstallDir}
       └─ ItemsControl.ItemsSource ← {Binding Tags}     ← IEnumerable<string>
            └─ DataTemplate  x:DataType="x:String"
                 └─ Border.Background
                      ← {Binding Converter={x:Static local:Converters.TagBrush}}
```

`Tags`는 `SteamGame`의 계산 프로퍼티(`SteamScanner.cs:81`)라서 별도 갱신 로직이 없습니다. 대신 **스캔 후 값이 바뀌어도 UI가 자동 갱신되지 않습니다** — `SteamGame`이 `INotifyPropertyChanged`를 구현하지 않기 때문입니다. 현재는 스캔이 끝난 뒤에만 컬렉션에 넣으므로 문제가 없습니다.

## 설계상의 트레이드오프

| 선택 | 얻은 것 | 잃은 것 |
|---|---|---|
| MVVM 없음 | 코드가 짧고 흐름이 직선적 | 기능 추가 시 code-behind 비대화 |
| 정적 스캐너 | 호출이 간단, 상태 없음, 병렬 호출 안전 | 파일시스템 목킹 불가 — 대신 임시 폴더 픽스처로 테스트 |
| `Marker`를 `ComboBoxItem.Tag`로 지정 | 항목 순서와 무관, 오타가 빌드 에러(AVLN2000) | XAML 이 조금 장황해짐 |
| 컴파일드 바인딩 | 바인딩 오타를 빌드 타임에 발견 | `x:DataType` 명시 필요 |
| `net10.0-windows` TFM | 레지스트리 API 직접 사용 | Avalonia인데도 Windows 전용 |
