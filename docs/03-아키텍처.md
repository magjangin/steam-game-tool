# 03. 아키텍처

## 전체 구조

MVVM이나 DI 컨테이너 없이, **화면 코드(`MainWindow`)가 스캔·내보내기·설치 코드를 직접 호출**합니다. 화면을 뺀 나머지는 Avalonia를 참조하지 않는 정적 클래스라서 테스트나 콘솔 앱에서 그대로 부를 수 있습니다.

```
┌──────────────────────────────────────────────────────────────┐
│ 진입점   Program.cs → App.axaml(.cs) → MainWindow              │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ 화면 (Avalonia, UI 스레드)                                     │
│   MainWindow.axaml(.cs)   레이아웃, 이벤트 핸들러, 요약·상태 줄 │
│   Converters.cs           태그 문자열 → 배지 색                 │
│   TextDialog.cs           긴 안내문 + 확인/닫기 대화 상자        │
│   상태: _last (마지막 스캔 전체), _view (지금 보기 목록)          │
└──────────────────────────────────────────────────────────────┘
        │ Task.Run (백그라운드)                    │
┌───────┴──────────────────────────────┐ ┌────────┴─────────────────────┐
│ 스캔                                  │ │ MelonLoader 설치              │
│   SteamScanner    조립·필터            │ │   MelonLoaderInstaller        │
│   SteamLibraries  스캔할 폴더 찾기     │ │     살피기·계획·설치·되돌리기  │
│   SteamCatalog    appmanifest·appinfo │ │   MelonLoaderReleases         │
│   UnityInspector  폴더 훑기·플레이어   │ │     버전 규칙, GitHub 다운로드 │
│   GameClassification 대표 플레이어    │ └──────────────────────────────┘
│ 모델                                  │
│   SteamGame, BackendEvidence,         │ ┌──────────────────────────────┐
│   ScanResult, Marker                  │ │ 내보내기·검증                 │
└───────────────────────────────────────┘ │   ExportLists  목록 정의·분할 검증 │
                                          │   GameExport   TXT 형식         │
      파일시스템 · 레지스트리 · GitHub       │   GameNames    이름 정규화      │
                                          │   ScanInventory 이전 스캔 대비 누락 검사 │
                                          └──────────────────────────────┘
```

### 계층 규칙

- **화면 밖 코드는 Avalonia를 모릅니다.** 예외는 `Converters`와 `TextDialog`뿐이고, 둘 다 화면 쪽입니다.
- **게임 폴더에 쓰는 곳은 `MelonLoaderInstaller.Install` 하나, 네트워크를 쓰는 곳은 `MelonReleaseClient` 하나입니다.** 스캔은 읽기만 합니다.
- **화면은 상태를 두 벌 듭니다.** `_last`는 스캔 결과 전체, `_view`는 현재 보기와 「게임만」을 통과한 부분집합입니다. 보기를 바꾸면 다시 스캔하지 않고 `_last`에서 다시 거릅니다(`ApplyFilter`).
- **ViewModel이 없습니다.** 그 대가로 `MainWindow.axaml.cs`가 가장 큰 파일 중 하나가 됐습니다(약 490줄).

## 파일별 역할

C# 19개 + XAML 2개, 약 2,900줄입니다. 테스트는 별도 프로젝트 `SteamGameTool.Tests`에 있습니다.

| 파일 | 역할 |
|---|---|
| `Program.cs` | `[STAThread]` 진입점, Avalonia `AppBuilder` 구성 |
| `App.axaml(.cs)` | Fluent 테마, `MainWindow` 생성 |
| `MainWindow.axaml(.cs)` | 화면 레이아웃과 모든 이벤트 핸들러 |
| `Converters.cs` | 태그 → 배지 색 변환기 |
| `TextDialog.cs` | MelonLoader 설치 확인·실패 안내 창 |
| `SteamScanner.cs` | 스캔 조립(`Scan`)과 보기 필터(`Filter`) |
| `SteamLibraries.cs` | 레지스트리·`libraryfolders.vdf`·흔한 위치·드라이브 최상위 보존본에서 스캔할 폴더 찾기 |
| `SteamCatalog.cs` | `appmanifest_*.acf`(이름·AppID)와 `appcache\appinfo.vdf`(앱 종류) 읽기 |
| `UnityInspector.cs` | 게임 폴더 훑기, 플레이어별 백엔드·런타임 판정 |
| `GameClassification.cs` | 대표 플레이어 고르기, 분류 분할 검증 |
| `SteamGame.cs` | 게임 폴더 하나의 모델, `UnityBackend`, `TagNames` |
| `BackendEvidence.cs` | 플레이어 하나의 관측 결과 |
| `ScanResult.cs` | 스캔 결과, 집계, `Marker`(보기·목록 종류) |
| `ExportLists.cs` | 목록 정의(파일명·헤더), TXT 저장, 저장 전 분할 검증 |
| `GameExport.cs` | TXT 형식, 점검용 JSON |
| `GameNames.cs` | 이름 정규화(nameKey) |
| `ScanInventory.cs` | 이전 스캔 대비 누락 검사, 스캔 기준선 파일 |
| `MelonLoaderInstaller.cs` | MelonLoader zip 확인, 게임 살피기, 설치 계획, 설치·되돌리기, 확인 창 문구 |
| `MelonLoaderReleases.cs` | 버전 규칙, GitHub 릴리스 목록·zip 다운로드와 캐시 |
| `app.manifest` | Windows 호환성 선언 (Avalonia 템플릿 기본값) |

## 데이터 흐름 — 스캔 한 번

「스캔 시작」을 누른 순간부터 목록이 뜰 때까지입니다.

```
[UI 스레드] OnScanClick
 1. 스캔 폴더 입력란 → roots (SteamLibraries.SplitRootList: 세미콜론·줄 바꿈으로만 나눔)
      비어 있음        → null (자동 감지)
      있는 폴더가 있음 → 그 폴더들. 없는 폴더는 상태 줄에 「건너뜀」으로 알림
      하나도 없음      → 상태 줄에 알리고 여기서 끝 (자동 감지로 넘어가지 않음, 이전 목록 유지)
 2. 버튼 끄기, 스피너, _view 비우기
                              │ await Task.Run
                              ▼
[백그라운드] SteamScanner.Scan(roots, progress)
 3. roots == null 이면 SteamLibraries.FindCommonFolders()
      레지스트리 → 드라이브마다 흔한 Steam 위치 → libraryfolders.vdf 를 따라 모든 라이브러리
      → 각 라이브러리의 steamapps\common + 드라이브 최상위의 보존본 게임 폴더
 4. SteamCatalog.Build()  appmanifest → 이름·AppID, appinfo.vdf → 앱 종류
 5. 루트마다
      단일 게임 폴더면(IsGameDirectory) 그 폴더 하나, 아니면 하위 폴더 전부
      Parallel.ForEach  ── 게임 폴더끼리 독립, I/O 바운드
        ├─ progress("검사 중: …")  → Dispatcher.UIThread.Post
        ├─ catalog.Find(폴더명)     → AppId·StoreName·AppType
        ├─ UnityInspector.Inspect  → 마커·플레이어 증거·백엔드 합집합
        ├─ 같은 이름 하위 폴더?      → HasNestedMatch
        └─ lock { Games / Warnings 에 추가 }
 6. NameKey 순 정렬 → ScanResult
[백그라운드, 같은 Task.Run 안]
 7. 분류 분할 검사 (GameClassification.Validate) — 대표 플레이어를 여기서 모두 계산
      어긋나면 예외 → 「스캔 중 오류」 (코드 버그일 때만)
    이전 스캔 대비 누락 검사 — 막지 않고 경고만 돌려줌
      기준선 파일과 비교·갱신 (ScanInventory.CheckPersistent)
      같은 세션·같은 루트의 직전 결과와도 비교 (ScanInventory.Check)
                              ▼
[UI 스레드]
 8. 이전 스캔에서 체크를 풀어 둔 게임은 새 결과에서도 풀기
 9. _last = result → ApplyFilter() → _view
10. 요약 줄(BuildSummary), 상태 줄(BuildStatus — 누락 검사 경고가 맨 앞)
11. finally: 스피너 숨기기, 버튼 켜기
```

**대표 플레이어는 게으르게 계산됩니다.** `SteamGame.Selection`은 처음 읽을 때 한 번 계산하고 저장합니다. 후보가 애매한 게임은 데이터 폴더 크기를 합산하므로([04-판별 로직](04-판별-로직.md)) 오래 걸릴 수 있어서, 7번에서 백그라운드로 미리 계산해 둡니다. 그 뒤 UI 스레드의 필터와 집계는 저장된 값을 읽기만 합니다.

**진행 메시지가 늦게 도착할 수 있습니다.** `Post`로 보낸 「검사 중: …」가 완료 뒤에 처리되면 결과 문구를 덮어쓰므로, 스캔이 끝난 뒤 도착한 진행 메시지는 버립니다. MelonLoader 설치도 같은 방식입니다.

## 스레딩 모델

| 작업 | 스레드 | 비고 |
|---|---|---|
| 스캔 | 백그라운드 (`Task.Run`) | 게임 폴더는 워커 여러 개 (`Parallel.ForEach`) |
| 대표 플레이어 계산, 누락 검사(기준선 파일 읽기·쓰기) | 백그라운드 (스캔과 같은 `Task.Run`) | |
| 진행 상황 | UI (`Dispatcher.UIThread.Post`) | 게임 폴더 하나마다 한 번 |
| 필터, 요약·상태 줄 | UI | 메모리 안의 목록 처리 |
| 「폴더 ▸ 자동 감지」 | 백그라운드 (`Task.Run`) | 모든 드라이브를 훑으므로 |
| TXT 저장 | UI (`async` 쓰기) | 「6개 모두 저장」은 `Task.Run` |
| MelonLoader 살피기·계획·설치 | 백그라운드 (`Task.Run`) | 설치는 게임 하나씩 차례로 |
| GitHub 목록·zip | 비동기 I/O | `HttpClient` 하나를 앱 전체가 씀 |

### 병렬 스캔의 계약

- **`progress` 콜백은 여러 스레드에서 동시에 불립니다.** 호출자가 스레드 안전해야 합니다. 화면은 `Post`로 넘기므로 안전합니다.
- **`ScanResult.Games`·`Warnings` 추가는 `lock`으로 보호합니다.** 카탈로그 경고는 병렬 구간 전에 한 스레드에서 쌓입니다.
- **결과 순서는 결정적입니다.** 모은 뒤 `NameKey` 순으로 정렬합니다.

### 알아 둘 것

- **취소 수단이 없습니다.** 스캔도 설치도 `CancellationToken`을 받지 않습니다([07-개선 로드맵](07-개선-로드맵.md) 5번).
- **`async void` 핸들러가 8개입니다**(`OnScanClick`, `OnBrowseClick`, `OnAddFolderClick`, `OnAutoClick`, `OnExportClick`, `OnExportAllClick`, `OnMelonAutoClick`, `OnMelonZipClick`). `async void`에서 예외가 새어 나가면 프로세스가 죽으므로 각 핸들러가 스스로 try/catch를 합니다. 파일·폴더 선택 창 호출도 try 안에 둡니다.
- **설치 중에는** 「MelonLoader 설치」 메뉴와 「스캔 시작」이 꺼집니다. 「저장」과 보기는 켜져 있습니다.

## 바인딩 구조

`AvaloniaUseCompiledBindingsByDefault`가 켜져 있어서 바인딩이 **컴파일 타임에 검증**됩니다. 그래서 `DataTemplate`마다 `x:DataType`이 필요합니다.

```
GameList.ItemsSource = _view                  (코드에서 설정)
  └─ DataTemplate  x:DataType="local:SteamGame"
       ├─ CheckBox.IsChecked ← {Binding InstallChecked}   (양방향)
       ├─ TextBlock ← {Binding DisplayName}
       ├─ TextBlock ← {Binding InstallDir}
       └─ ItemsControl.ItemsSource ← {Binding Tags}
            └─ DataTemplate  x:DataType="x:String"
                 └─ Border.Background ← {Binding Converter={x:Static local:Converters.TagBrush}}
```

`SteamGame`은 `INotifyPropertyChanged`를 구현하지만 **`InstallChecked`만** 알립니다. 목록 체크와 「MelonLoader 설치 대상」 전체 체크박스가 서로 따라가게 하려는 것입니다. 나머지 속성은 스캔이 끝난 뒤 바뀌지 않으므로 알리지 않습니다.

보기 콤보박스는 항목마다 `Tag="{x:Static local:Marker.…}"`를 답니다. 코드는 순서가 아니라 이 `Tag`로 보기를 읽고(`SelectedMarker`), 「6개 모두 저장」도 이 항목들을 그대로 따릅니다.

## 설계상의 트레이드오프

| 선택 | 얻은 것 | 잃은 것 |
|---|---|---|
| MVVM 없음 | 코드가 짧고 흐름이 직선적 | 기능이 늘수록 `MainWindow.axaml.cs`가 비대해짐 |
| 정적 클래스 | 호출이 간단, 상태 없음, 병렬 호출 안전 | 파일시스템을 가짜로 바꿀 수 없음 — 대신 임시 폴더 픽스처로 테스트 |
| 실제 임시 폴더로 테스트 | 스캐너를 고치지 않고 그대로 검증 | 테스트가 디스크를 씀 |
| `Marker`를 `ComboBoxItem.Tag`로 | 항목 순서와 무관, 이름 오타는 빌드 에러(AVLN2000) | XAML이 조금 장황함 |
| 컴파일드 바인딩 | 바인딩 오타를 빌드 때 발견 | `x:DataType` 명시 필요 |
| `net10.0-windows` | 레지스트리 API 직접 사용 | Avalonia인데도 Windows 전용 |
