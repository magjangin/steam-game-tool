## ✅ 1. 스캔 성능 — 완료

**문제였던 것.** `InspectUnityInstall`이 `RecurseSubdirectories = true`만 지정하고 깊이 제한이 없어서 게임 폴더를 끝까지 훑었습니다. 수십만 파일짜리 대형 게임도 전부 순회했습니다.

**한 것.**

| 조치 | 내용 |
|---|---|
| 깊이 상한 | `MaxRecursionDepth = MaxScanDepth`(8) — `SteamScanner.cs:146`, `:272` |
| 조기 종료 | Mono·IL2CPP·`Managed`가 모두 확정되면 `break` — `SteamScanner.cs:370` |
| 병렬화 | 게임 폴더 단위 `Parallel.ForEach` + `lock` — `SteamScanner.cs:283`, `:230` |

**결과** (실제 라이브러리, 게임 885개):

| 단계 | 소요 시간 |
|---|---:|
| 개선 전 | 137.6초 |
| 깊이 상한 + 조기 종료 | 3.5초 |
| \+ 병렬화 | **0.7초** |

**검증.** 게임 885개의 이름·백엔드·마커를 전부 덤프해 개선 전후로 대조한 결과 **완전히 일치**했습니다. 병렬화 후 3회 반복 실행에서도 동일한 결과가 나와 순서 결정성을 확인했습니다.

깊이 상한의 근거가 되는 실측 분포는 [04-판별 로직](04-판별-로직.md)「깊이 상한」에 있습니다.

## ✅ 2. `Marker` ↔ 콤보박스 결합 — 완료

**문제였던 것.** `(Marker)Math.Max(0, FilterCombo.SelectedIndex)`로 필터를 얻어서, XAML 항목 순서와 열거형 순서가 우연히 일치하는 데 기대고 있었습니다. 항목 하나만 끼워 넣어도 컴파일 에러 없이 잘못된 필터가 적용됐습니다.

**한 것.** 각 `ComboBoxItem`에 `Tag="{x:Static local:Marker.…}"`를 달고 (`MainWindow.axaml:33-38`), `SelectedMarker` 프로퍼티가 그 `Tag`를 읽습니다 (`MainWindow.axaml.cs:30`).

**검증.** 열거형 이름에 오타를 넣으면 `AVLN2000 — Unable to resolve "Marker.…"` 빌드 에러가 나는 것을 확인했습니다. 이제 순서와 무관하고, 잘못된 이름은 빌드가 막습니다.

## ✅ 3. AppID·실제 게임 이름 — 완료

**문제였던 것.** 게임 이름이 **디스크 폴더명**이었습니다. 폴더명은 스토어 표기와 다른 경우가 아주 많고(`HatinTime` → `A Hat in Time`, `game` → `99 Games: …`), AppID 도 알 수 없었습니다.

**한 것.** 각 라이브러리의 `steamappsppmanifest_<appid>.acf` 를 읽어 AppID·스토어명·설치 폴더를 얻습니다 (`SteamCatalog.cs:74`). 목록·정렬·내보내기가 모두 **스토어 표기 이름**을 씁니다.

여기서 얻은 AppID 는 9번(앱 종류 판별)의 열쇠이기도 합니다.

**남은 것:** 항목 더블클릭 → 폴더 열기 / `steam://run/<appid>` 실행, 내보내기에 AppID 포함 (6번과 함께).


## ✅ 4. 하드코딩된 개인 경로 — 완료

**문제였던 것.** `C:\Program Files (x86)\Steam`, `H:\steam`, `H:\SteamLibrary` 세 경로가 소스에 박혀 있었습니다. 뒤의 둘은 개발자 개인 PC의 경로입니다.

**한 것.** Steam 기본 설치 위치 하나만 폴백으로 남기고 나머지를 제거했습니다 (`SteamScanner.cs:203`). "개인 환경 경로를 추가하지 말 것"이라는 주석을 함께 남겼습니다.

**검증 과정에서 확인한 것.** 이 PC에서는 레지스트리가 `h:/steam`을 정확히 가리키고, 그 `libraryfolders.vdf`가 실제 라이브러리(게임 885개)를 담고 있습니다. 즉 **하드코딩 없이도 자동 감지가 정상 동작**합니다. 흥미롭게도 `C:` 쪽 vdf는 이미 존재하지 않는 `H:\SteamLibrary`를 가리키는 낡은 항목을 갖고 있었는데, 레지스트리 경로를 우선 읽는 현재 로직에서는 문제가 되지 않습니다.

## ⬜ 5. 취소 불가 + 진행률 없음

**문제.**

- `Scan()`이 `CancellationToken`을 받지 않습니다 (`SteamScanner.cs:239`).
- `ProgressBar`가 `IsIndeterminate="True"`라 얼마나 남았는지 알 수 없습니다.
- `progress` 콜백이 게임 폴더마다 `Dispatcher.UIThread.Post`를 호출합니다 (`MainWindow.axaml.cs:48`).

**개선안.**

- `Scan(roots, progress, CancellationToken)`으로 확장. `Parallel.ForEach`는 `ParallelOptions.CancellationToken`으로 바로 받을 수 있습니다. 「스캔 시작」 버튼을 스캔 중에 「취소」로 바꿉니다.
- 시작 전에 게임 폴더 개수를 세어 `Maximum`을 설정하고 determinate로 전환.
- 진행 상황 텍스트는 스로틀링 (예: 100ms마다 최신 값만 반영).

**우선순위가 내려갔습니다.** 1번 이후 전체 스캔이 0.7초로 끝나므로 취소할 일이 사실상 없습니다. 훨씬 큰 라이브러리나 느린 네트워크 드라이브를 다룰 때 다시 검토하세요.

### `" Demo"` 예외에 대한 판단 요청

이름에 `" Demo"`가 든 게임은 `Managed` 태그가 강제로 꺼집니다. 백엔드 판정에는 영향이 없습니다.

- 의도가 "체험판을 `Managed` 목록에서 제외"라면 → 지금 동작이 맞고, 근거만 주석으로 남기면 됩니다 (임시 주석은 이미 달아 두었습니다)
- 실수이거나 더 이상 필요 없다면 → 제거

현재 동작은 `ScanAndFilterTests.이름에_Demo가_들어가면_Managed_마커만_꺼진다`가 고정하고 있으므로, 어느 쪽으로 정하든 테스트를 함께 고치면 됩니다.

## ⬜ 8. 크로스플랫폼 — 보류

**문제.** Avalonia는 크로스플랫폼인데 TFM은 `net10.0-windows`입니다. 이유는 `Microsoft.Win32.Registry` 하나뿐입니다.

**개선안.** TFM을 `net10.0`으로 낮추고 레지스트리 접근을 `OperatingSystem.IsWindows()`로 가드합니다. Linux/macOS에서는 알려진 Steam 경로를 씁니다.

| OS | Steam 기본 경로 |
|---|---|
| Linux | `~/.steam/steam`, `~/.local/share/Steam` |
| macOS | `~/Library/Application Support/Steam` |

`libraryfolders.vdf` 형식은 플랫폼 공통이라 파싱 코드는 그대로 씁니다. 테스트 프로젝트의 TFM도 함께 내려야 합니다.

**쓰는 사람이 Windows뿐이라면 하지 않는 것도 정답입니다.**

## ✅ 9. 게임/사운드트랙·도구 구분 — 완료

**문제였던 것.** `steamapps\common` 폴더 수를 그대로 게임 수로 보여 줬습니다. 거기엔 사운드트랙·소프트웨어·도구와, 삭제 후 남은 잔여 폴더가 섞여 있습니다.

**한 것.** `appcacheppinfo.vdf`(Valve 의 바이너리 VDF)를 파싱해 앱 종류를 읽고, 집계와 목록을 게임 기준으로 좁혔습니다. 「게임만」 체크박스도 추가했습니다.

**결과** (실측 라이브러리):

| | 개수 |
|---|---:|
| `common` 폴더 전체 | 893 |
| **게임** | **844** |
| 소프트웨어 | 11 |
| 도구 | 2 |
| 데모 | 1 |
| 미설치 잔여 폴더 | 36 |

폴더 수를 게임 수라고 부르면 **49개(5.5%)가 부풀려집니다.**

**안전장치.** `appinfo.vdf` 는 Valve 의 비공개 포맷이라 언제든 바뀔 수 있습니다. 못 읽으면 종류 없이 동작하고, 화면은 "게임 N개" 대신 "폴더 N개"로 바뀝니다. 종류를 모르는 앱은 게임 쪽에 남겨 둡니다 — **확실히 게임이 아닌 것만** 배제합니다.

자세한 내용은 [09-앱 종류 판별](09-앱-종류-판별.md).
