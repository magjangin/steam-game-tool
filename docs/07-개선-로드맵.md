## ✅ 1. 스캔 성능 — 완료

**문제였던 것.** 폴더 검사가 깊이 제한 없이 게임 폴더를 끝까지 훑었습니다. 수십만 파일짜리 대형 게임도 전부 순회했습니다.

**한 것.**

| 조치 | 내용 |
|---|---|
| 깊이 상한 | `UnityInspector.MaxScanDepth` = 8 |
| 한 번만 훑기 | 보조 마커와 데이터 폴더를 한 번의 순회로 모음 (`UnityInspector.Walk`) |
| 병렬화 | 게임 폴더 단위 `Parallel.ForEach` + `lock` (`SteamScanner.Scan`) |

**결과** (당시 실제 라이브러리, 게임 885개):

| 단계 | 소요 시간 |
|---|---:|
| 개선 전 | 137.6초 |
| 깊이 상한 + 조기 종료 | 3.5초 |
| \+ 병렬화 | **0.7초** |

**검증.** 게임 885개의 이름·백엔드·마커를 전부 덤프해 개선 전후로 대조한 결과 **완전히 일치**했습니다. 병렬화 후 3회 반복 실행에서도 동일한 결과가 나와 순서 결정성을 확인했습니다.

이 시간들은 디스크 캐시가 찬 상태의 값입니다. 처음 스캔은 14번을 보세요. 깊이 상한의 근거는 [04-판별 로직](04-판별-로직.md)「깊이 상한」에 있습니다.

## ✅ 2. `Marker` ↔ 콤보박스 결합 — 완료

**문제였던 것.** `(Marker)Math.Max(0, FilterCombo.SelectedIndex)`로 필터를 얻어서, XAML 항목 순서와 열거형 순서가 우연히 일치하는 데 기대고 있었습니다. 항목 하나만 끼워 넣어도 컴파일 에러 없이 잘못된 필터가 적용됐습니다.

**한 것.** 각 `ComboBoxItem`에 `Tag="{x:Static local:Marker.…}"`를 달고, `MainWindow.SelectedMarker`가 그 `Tag`를 읽습니다.

**검증.** 열거형 이름에 오타를 넣으면 `AVLN2000 — Unable to resolve "Marker.…"` 빌드 에러가 나는 것을 확인했습니다.

## ✅ 3. AppID·실제 게임 이름 — 완료

**문제였던 것.** 게임 이름이 **디스크 폴더명**이었습니다. 폴더명은 스토어 표기와 다른 경우가 아주 많고(`HatinTime` → `A Hat in Time`, `game` → `99 Games: …`), AppID도 알 수 없었습니다.

**한 것.** 각 라이브러리의 `steamapps\appmanifest_<appid>.acf`를 읽어 AppID·스토어명·설치 폴더를 얻습니다(`SteamCatalog.Build`). 목록·정렬·내보내기가 모두 **스토어 표기 이름**을 씁니다.

여기서 얻은 AppID는 9번(앱 종류 판별)의 열쇠이기도 합니다.

**남은 것:** 항목 더블클릭 → 폴더 열기 / `steam://run/<appid>` 실행 (6번과 함께).

## ✅ 4. 하드코딩된 개인 경로 — 완료

**문제였던 것.** `C:\Program Files (x86)\Steam`, `H:\steam`, `H:\SteamLibrary` 세 경로가 소스에 박혀 있었습니다. 뒤의 둘은 개발자 개인 PC의 경로입니다.

**한 것.** 특정 PC의 경로를 뺐습니다. 이 PC에서는 레지스트리가 `h:/steam`을 정확히 가리키고, 그 `libraryfolders.vdf`가 실제 라이브러리를 담고 있어 하드코딩 없이도 자동 감지가 정상 동작합니다.

**그 뒤 바뀐 것.** 자동 감지가 다시 넓어졌습니다. 지금은 드라이브마다 흔한 Steam 위치(`Steam`, `SteamLibrary`, `Games\Steam` 등)를 확인하고, 드라이브 최상위의 Unity 게임 폴더도 찾습니다(`SteamLibraries.FindCommonFolders`). 특정 PC의 경로는 아니지만 건너뛰는 목록에 개발 PC 환경의 이름이 남아 있습니다 → 15번.

## ⬜ 5. 취소 불가 + 진행률 없음

**문제.**

- `SteamScanner.Scan`이 `CancellationToken`을 받지 않습니다. MelonLoader 설치도 마찬가지입니다.
- `ProgressBar`가 `IsIndeterminate="True"`라 얼마나 남았는지 알 수 없습니다.
- `progress` 콜백이 게임 폴더마다 `Dispatcher.UIThread.Post`를 호출합니다.

**개선안.**

- `Scan(roots, progress, catalog, CancellationToken)`으로 확장. `Parallel.ForEach`는 `ParallelOptions.CancellationToken`으로 바로 받을 수 있습니다. 「스캔 시작」 버튼을 스캔 중에 「취소」로 바꿉니다.
- 시작 전에 게임 폴더 개수를 세어 `Maximum`을 설정하고 determinate로 전환.
- 진행 상황 텍스트는 스로틀링 (예: 100ms마다 최신 값만 반영).

다시 스캔은 1초 안에 끝나지만 처음 스캔은 1분 넘게 걸릴 수 있어서(14번) 필요성이 다시 생겼습니다.

## ⬜ 8. 크로스플랫폼 — 보류

**문제.** Avalonia는 크로스플랫폼인데 TFM은 `net10.0-windows`입니다. 이유는 레지스트리(`Microsoft.Win32.Registry`)입니다.

**개선안.** TFM을 `net10.0`으로 낮추고 레지스트리 접근을 `OperatingSystem.IsWindows()`로 가드합니다. Linux/macOS에서는 알려진 Steam 경로를 씁니다.

| OS | Steam 기본 경로 |
|---|---|
| Linux | `~/.steam/steam`, `~/.local/share/Steam` |
| macOS | `~/Library/Application Support/Steam` |

`libraryfolders.vdf` 형식은 플랫폼 공통이라 파싱 코드는 그대로 씁니다. 테스트 프로젝트의 TFM도 함께 내려야 합니다. MelonLoader 설치(PE 헤더, `version.dll` 프록시)는 Windows 게임 기준이라 따로 따져야 합니다.

**쓰는 사람이 Windows뿐이라면 하지 않는 것도 정답입니다.**

## ✅ 9. 게임/사운드트랙·도구 구분 — 완료

**문제였던 것.** `steamapps\common` 폴더 수를 그대로 게임 수로 보여 줬습니다. 거기엔 사운드트랙·소프트웨어·도구와, 삭제 후 남은 잔여 폴더가 섞여 있습니다.

**한 것.** `appcache\appinfo.vdf`(Valve의 바이너리 VDF)를 파싱해 앱 종류를 읽고, 집계와 목록을 게임 기준으로 좁혔습니다. 「게임만」 체크박스도 추가했습니다.

**결과** (당시 실측 라이브러리):

| | 개수 |
|---|---:|
| `common` 폴더 전체 | 893 |
| **게임** | **844** |
| 소프트웨어 | 11 |
| 도구 | 2 |
| 미설치 잔여 폴더 | 36 |

폴더 수를 게임 수라고 부르면 **49개(5.5%)가 부풀려집니다.** (데모 1개는 게임 844개 안에 들어 있습니다.)

**안전장치.** `appinfo.vdf`는 Valve의 비공개 포맷이라 언제든 바뀔 수 있습니다. 못 읽으면 종류 없이 동작하고, 화면은 "게임 N개" 대신 "폴더 N개"로 바뀝니다. 종류를 모르는 앱은 게임 쪽에 남겨 둡니다 — **확실히 게임이 아닌 것만** 배제합니다.

자세한 내용은 [09-앱 종류 판별](09-앱-종류-판별.md).

## ✅ 10. 누락 검사에 한 번 걸리면 스캔이 계속 막힘 — 완료

**문제였던 것.** `ScanInventory`는 이전에 Unity였던 폴더가 디스크에 남아 있는데 이번에 Unity가 아니면 예외를 던졌습니다. 예외가 기준선 갱신보다 먼저라서 **그 폴더를 치우기 전까지 모든 스캔이 실패**했고, 화면은 빈 목록과 영어 메시지만 보여 줬습니다.

**재현** (2026-09-22, 임시 라이브러리): Unity 게임 폴더로 1회 스캔 → `*_Data`와 exe를 지우고 `MelonLoader\`·`Mods\`·`version.dll`만 남김 → 2·3·4회 스캔이 모두 `Unity classification regression…`으로 실패.

**일어나기 쉬운 경우.** MelonLoader를 깐 게임을 Steam에서 제거하면, Steam이 설치하지 않은 `MelonLoader\`·`Mods\`·`UserData\` 때문에 폴더가 남을 수 있습니다.

**한 것.** [AGENTS.md](../AGENTS.md)가 이 검사를 유지하라고 하므로 검사는 그대로 두고, 막는 대신 경고로 바꿨습니다(`ScanInventory.CheckPersistent`).

- 스캔 결과와 목록은 그대로 보여 주고, 걸린 폴더는 상태 줄 맨 앞에 「⚠ 전에 Unity 로 분류됐는데 지금은 아닌 폴더 N개: …」로 알립니다.
- 걸린 폴더를 새 기준선에도 남겨서, 폴더를 지우거나 다시 Unity로 판정될 때까지 **매번** 알립니다. 조용히 사라지지 않습니다.
- 기준선 파일 이름 계산은 그대로라 기존 기준선을 계속 씁니다. 깨진 기준선 파일은 새로 만듭니다.

**검증.** 위 재현을 앱 화면(헤드리스)으로 다시 돌렸습니다. 2·3회 스캔 모두 목록이 나오고 경고가 보였고, 폴더를 지운 4회째에는 경고가 사라졌습니다. `ScanInventoryTests`가 같은 흐름을 고정합니다.

## ✅ 11. 스캔 폴더 입력란 — 완료

**문제였던 것.**

- `OnScanClick`이 입력란을 `;`뿐 아니라 `,`로도 나눴습니다. Windows 경로에는 쉼표가 들어갈 수 있습니다(`D:\Games, Old\steamapps\common`). 「폴더 추가…」는 `;`로만 이어 붙여서 둘이 어긋났습니다.
- 입력한 경로가 하나도 없으면 아무 말 없이 자동 감지로 넘어갔습니다. 한 폴더만 보려던 사용자가 전체 라이브러리 결과를 받았습니다.

**한 것.** 입력란은 `SteamLibraries.SplitRootList`가 세미콜론과 줄 바꿈으로만 나눕니다(앞뒤 따옴표도 뗌). 입력한 폴더가 하나도 없으면 스캔하지 않고 「입력한 폴더가 없습니다: …」를 보여 주며 이전 목록을 그대로 둡니다. 일부만 없으면 있는 것만 스캔하고 「⚠ 입력한 폴더 중 없는 것은 건너뜀」을 보여 줍니다. 앱 화면에서 쉼표 경로, 없는 경로, 일부만 없는 경우를 확인했습니다.

## ✅ 12. 화면 스레드에서 도는 무거운 작업 — 완료

**문제였던 것.**

- 「폴더 ▸ 자동 감지」가 `FindCommonFolders()`를 UI 스레드에서 바로 불렀습니다. 모든 드라이브를 훑으므로 네트워크 드라이브나 잠든 외장 디스크가 있으면 창이 멈출 수 있었습니다.
- 스캔 뒤의 검사가 대표 플레이어(`SteamGame.Selection`)를 UI 스레드에서 처음 계산했습니다. 동률 게임은 데이터 폴더 크기를 전부 더하므로 그만큼 창이 멈췄습니다(2026-09-22 실측: 처음 스캔 직후 332ms, 다시 스캔 뒤 21~32ms).
- `OnExportClick`의 저장 창 호출이 try 밖에 있었습니다. `async void`라 여기서 예외가 나면 앱이 꺼질 수 있었습니다.

**한 것.** 자동 감지는 `Task.Run`으로 돌리고 그동안 「Steam 라이브러리를 찾는 중...」을 보여 줍니다. 대표 플레이어 계산과 누락 검사(기준선 파일 읽기·쓰기)는 스캔과 같은 `Task.Run` 안으로 옮겼습니다. 저장 창 호출도 try 안에 넣었습니다. 스캔이 끝난 뒤 도착한 진행 메시지는 버려서 결과 문구를 덮어쓰지 않게 했습니다.

## ✅ 13. 요약·상태 줄의 숫자 기준 — 완료

**문제였던 것.**

- 요약 줄의 「게임 N개」/「폴더 N개」는 `HasTypeInfo`로 고르는데, 「폴더」일 때는 전체 폴더 수를, 뒤의 개수들은 `CountedGames`를 썼습니다. `appinfo.vdf`만 못 읽으면 분모와 분자의 범위가 달랐습니다.
- 상태 줄 「제외: …」에 「데모」가 들어 있었지만 데모는 게임으로 셉니다(`IsGameLike`). 2026-09-22 실측에서 게임 918 + 소프트웨어 12 + 도구 2 + 잔여 36 = 폴더 968이었고, 데모 1개는 918 안에 있었습니다.
- `Config`·`Other` 종류는 게임에서 빠지지만 「제외」에 나오지 않았습니다.

**한 것.** 요약 줄의 전체 수는 라벨과 상관없이 `GameCount`를 씁니다. 「제외」에서 데모를 빼고 `Config`·`Other`를 「기타」로 넣었습니다. 실제 라이브러리에서 게임 917 + 제외 14 + 잔여 36 = 폴더 967로 맞는 것을 확인했습니다.

## ⬜ 14. 첫 스캔이 느림

2026-09-22 이 PC(폴더 968개)에서 컴퓨터를 켜고 처음 스캔하니 약 98초, 이어서 다시 하면 약 1초였습니다. 디스크 캐시가 빈 상태에서 폴더 목록과 Steam 파일을 읽는 비용으로 보입니다. 어느 단계(카탈로그, 드라이브 최상위 탐색, 게임 폴더 순회)가 시간을 쓰는지는 아직 재지 않았습니다.

## ⬜ 15. 자동 감지의 드라이브 최상위 탐색

`SteamLibraries.FindPreservedGameFolders`는 모든 드라이브의 최상위 폴더 중 Unity 게임처럼 생긴 것을 스캔 대상에 넣습니다. Steam 밖에 복사해 둔 게임(이 PC에서는 `H:\muse dash hwa`와 `H:\Sixtar Gate STARTRAIL …` 7개)을 위한 기능입니다.

- 건너뛰는 폴더 목록에 `source`, `steam`, `SteamLibrary`가 있습니다. `source`는 개발 PC의 저장소 폴더 이름입니다.
- 드라이브 최상위에 둔 자기 Unity 빌드 결과물도 게임으로 잡힐 수 있습니다.
- 이 동작을 끄는 옵션은 없습니다. 입력란에 폴더를 직접 적으면 그 폴더만 스캔합니다.
