# 10. 이름과 내보내기

> 목록에 쓰는 이름, TXT 형식, 저장 범위, 저장 전 검증, 이전 스캔 대비 누락 검사를 다룹니다.
> 어떤 게임이 어느 목록에 들어가는지는 [04-판별 로직](04-판별-로직.md), 게임과 비게임 구분은 [09-앱 종류 판별](09-앱-종류-판별.md)에 있습니다.

## 이름 — 화면 이름과 nameKey

게임마다 이름이 두 가지입니다.

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `DisplayName` | 스토어 이름, 없으면 폴더 이름. **손대지 않습니다** | 화면 목록 |
| `NameKey` | `DisplayName`을 정규화한 것 | 정렬, TXT |

정규화(`GameNames.Normalize`)는 네 가지만 합니다.

1. 유니코드 NFC 정규화 — `Ro` + 결합 분음 기호 + `ki` → `Röki`
2. 곡선 아포스트로피 `‘` `’` → `'` — `Erza’s Wheel of Fortune` → `Erza's Wheel of Fortune`
3. 연속된 공백(줄 바꿈 없는 공백 U+00A0 등 유니코드 공백 포함) → 공백 하나 — `Aotenjo:` + U+00A0 + `Infinite Hands` → `Aotenjo: Infinite Hands`
4. 앞뒤 공백 제거 — ` Marfusha` → `Marfusha`

설치 경로(`InstallDir`)도 그대로 둡니다. 정규화는 비교와 출력용일 뿐 원본을 바꾸지 않습니다.

## TXT 형식

```
Unity Mono games classified by the selected player:

1. Cuphead
2. Hollow Knight
3. …

Total: 699
```

- 첫 줄은 목록마다 정해진 영문 헤더(`ExportLists.All`), 그다음 빈 줄
- `번호. nameKey`, 번호는 1부터. `NameKey` 순(대소문자 무시)
- 빈 줄, `Total: N`
- 줄 끝은 CRLF, 인코딩은 **BOM 없는 UTF-8**

## 저장 두 가지

| 메뉴 | 만드는 파일 | 파일명 |
|---|---|---|
| 「저장 ▸ TXT로 저장…」 | 지금 보기 목록 **하나** | 저장 창에 기본값으로 보기별 이름이 들어갑니다. 바꿔도 됩니다 |
| 「저장 ▸ 6개 모두 저장…」 | 보기 6개를 고른 폴더에 **한 번에** | 아래 고정 이름. 같은 이름 파일은 덮어씁니다 |

| 보기 | 파일명 |
|---|---|
| 전체 Unity 게임 (Mono + IL2CPP) | `list_unity_games.txt` |
| Unity Mono | `list_unity_mono_games.txt` |
| Mono (구형 레거시 - Data/Mono) | `list_legacy_mono_games.txt` |
| MonoBleedingEdge | `list_monobleedingedge_games.txt` |
| Unity IL2CPP | `list_unity_il2cpp_games.txt` |
| 중첩 (Unity 게임) | `list_nested_unity_games.txt` |

- 두 메뉴의 내용은 같습니다. 「6개 모두 저장」의 각 파일은 그 보기에서 「TXT로 저장」한 것과 바이트까지 같습니다(`NormalizationExportTests`가 고정).
- 어느 쪽도 검증용 목록, 별칭 파일, JSON을 옆에 따로 만들지 않습니다([AGENTS.md](../AGENTS.md)).
- **범위:** 「게임만」이 켜져 있으면 집계 대상(`CountedGames`)만, 꺼져 있으면 스캔한 모든 폴더에서 거릅니다. 한 번 저장하는 동안 모든 목록이 같은 범위를 씁니다.

`ExportLists.All`에는 목록 정의가 15개 있습니다. 앱이 쓰는 것은 위 6개이고, 나머지(`list_scanned_games.txt`, `list_backend_unresolved.txt` 등)는 저장 전 검증과 점검용입니다. 전체 표는 [05-코드 레퍼런스](05-코드-레퍼런스.md)「`enum Marker`」에 있습니다.

## 저장 전 검증

저장하기 전에 `ExportLists.Validate`가 **실제 필터 결과로** 분할이 맞는지 확인합니다. 하나라도 어긋나면 「저장 실패: …」를 띄우고 파일을 만들지 않습니다. 「6개 모두 저장」은 모든 본문을 만든 뒤에 쓰므로 일부 파일만 남는 일이 없습니다.

| 검사 | 뜻 |
|---|---|
| 스캔 범위 = Mono ∪ IL2CPP ∪ 백엔드 미확정 | 모든 게임이 셋 중 정확히 하나에 들어감 |
| Mono = 구형 레거시 ∪ MonoBleedingEdge ∪ 런타임 미확정 | Mono 게임이 셋 중 정확히 하나에 들어감 |
| 스캔 범위 = Unity ∪ 비Unity ∪ 플레이어 미확정 | Unity 근거가 조금이라도 있거나 Steam 종류를 모르는 항목은 「비Unity」로 세지 않음 |
| 중첩(Unity) ⊆ Unity ∪ 플레이어 미확정 | 중첩 목록에만 있고 다른 목록에서 빠진 게임이 없음 |

- **백엔드 미확정**은 「Unity가 아니다」가 아닙니다. 대표 플레이어를 정하지 못했다는 뜻이고, Unity 근거가 있는데 판정하지 못한 항목도 들어 있습니다.
- **비Unity**(`NonUnity`)는 Steam에 종류가 알려져 있고 Unity 흔적이 전혀 없는 항목입니다. 엔진을 확인했다는 뜻은 아닙니다.

## 중첩 신호 두 가지

| 신호 | 기준 | 보이는 곳 |
|---|---|---|
| 구조 기반 (`HasNestedUnity`) | 설치 폴더 바로 아래가 아닌 곳에 백엔드가 정해진 Unity 플레이어가 있음 | 보기 「중첩 (Unity 게임)」, `list_nested_unity_games.txt` |
| 같은 이름 하위 폴더 (`HasNestedMatch`) | `Foo\Foo\`처럼 설치 폴더 안에 같은 이름의 폴더가 있음 | 배지 「중첩」 |

두 신호는 따로 보존합니다. 같은 이름 폴더 신호 쪽 목록(`list_samename_game_folders.txt`, `list_shadowed_name_games.txt`, `list_samename_no_unity_detected_games.txt`)은 점검용이라 보기에는 없습니다. 예: Jaded는 `Jaded\Jaded\` 폴더가 있어 배지는 붙지만, 플레이어가 설치 폴더 바로 아래에 있어 「중첩」 보기에는 나오지 않습니다.

## 이전 스캔 대비 누락 검사

게임이 분류에서 **조용히 사라지는 것**을 막는 검사입니다(`ScanInventory`). 스캔할 때마다 돌고, 걸리면 목록을 보여 주지 않고 「스캔 중 오류가 발생했습니다」로 멈춥니다.

| 검사 | 오류가 되는 경우 | 메시지 |
|---|---|---|
| 폴더 누락 | 이전 스캔에 있던 폴더가 **디스크에는 아직 있는데** 이번 결과에 없음 | `Existing installation folders disappeared from scan: …` |
| Unity 분류 누락 | 이전에 Unity(보기 「전체 Unity 게임」)였던 폴더가 **디스크에는 아직 있는데** 이번에는 Unity가 아님 | `Unity classification regression for installed entries: …` |

- 폴더가 디스크에서 실제로 없어졌으면 오류가 아닙니다. 게임을 지운 것이기 때문입니다.
- 비교 대상은 두 가지입니다. 앱을 켠 동안 같은 루트를 다시 스캔하면 직전 결과와, 앱을 다시 켜면 **기준선 파일**과 비교합니다.
- 기준선 파일은 `%LOCALAPPDATA%\SteamGameTool\scan-baselines\<루트 해시>.json`입니다. 스캔한 루트 구성마다 파일이 하나씩이고, 검사를 통과할 때만 갱신됩니다.
- **검사에 걸리면 그 상태가 풀릴 때까지 매번 걸립니다.** 기준선이 갱신되지 않기 때문입니다. 흔한 경우는 Steam에서 게임을 제거했는데 `MelonLoader\`·`Mods\`처럼 Steam이 설치하지 않은 파일 때문에 폴더가 남은 경우입니다. 메시지에 나온 폴더를 지우거나, 그대로 둘 폴더라면 해당 기준선 파일을 지우면 풀립니다. 기준선을 지우면 그다음 스캔이 새 기준선이 됩니다.
- 이 검사는 실행 설정 변경이나 경로가 같은 재설치까지 알아내지는 못합니다.

## 점검용 출력

`GameExport.ToJson`은 게임마다 분류, 대표 플레이어와 선택 이유·신뢰도, 플레이어별 증거를 담은 JSON(`schemaVersion` 4)을 만듭니다. 앱은 이것을 쓰지 않습니다. 예전에는 저장소 밖의 점검 도구(audit)가 이 JSON과 15개 목록 전부를 만들었지만, 그 도구는 이 저장소에 없습니다. 앱의 저장 형식은 TXT뿐입니다.
