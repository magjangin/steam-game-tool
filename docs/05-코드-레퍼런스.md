# 05. 코드 레퍼런스

> 파일·타입·멤버별 명세입니다. 공개 API를 바꾸면 이 문서를 함께 고칩니다.
> 판별 규칙의 근거는 [04-판별 로직](04-판별-로직.md), 구조와 흐름은 [03-아키텍처](03-아키텍처.md)에 있습니다.

네임스페이스는 전부 `steam_game_tool`입니다(폴더명의 공백이 `_`로 바뀐 이름). 코드 위치는 줄 번호 대신 `타입.멤버`로 적습니다.

# 모델

## `SteamGame.cs`

### `enum UnityBackend` — `[Flags]`

| 값 | 비트 | 뜻 |
|---|---|---|
| `Unknown` | 0 | Unity 백엔드 근거 없음 |
| `Mono` | 1 | Mono 플레이어가 하나 이상 |
| `Il2Cpp` | 2 | IL2CPP 플레이어가 하나 이상 |
| `Mono \| Il2Cpp` | 3 | 한 폴더에 둘 다 (런처 + 본편 등) |

`SteamGame.Backend`는 플레이어 판정의 합집합이라 3이 될 수 있습니다. 대표 플레이어의 판정(`ClassifiedBackend`)은 0·1·2 중 하나입니다.

### `static class TagNames`

배지 문자열의 단일 정의처입니다. `SteamGame.Tags`와 `Converters.TagBrush`가 같은 상수를 씁니다. 태그를 추가할 때는 여기에 상수를 만들고 양쪽에서 참조합니다.

| 상수 | 값 |
|---|---|
| `UnityMono` | `"Unity Mono"` |
| `UnityIl2Cpp` | `"Unity IL2CPP"` |
| `MonoBleedingEdge` | `"MonoBleedingEdge"` |
| `Managed` | `"Managed"` |
| `Nested` | `"중첩"` |

## `BackendEvidence.cs`


플레이어 하나의 관측 결과입니다. 경로는 모두 설치 폴더 기준 상대 경로입니다. 각 값의 뜻은 [04-판별 로직](04-판별-로직.md)「함께 기록하는 것」.

| 멤버 | 설명 |
|---|---|
| `DataPath` | `*_Data` 경로. 런타임만 있는 위치는 `null` |
| `Layer` | `outer` / `inner` |
| `Backend`, `Rule` | 판정과 그 근거 규칙 |
| `PlayerPath`, `ExecutablePath`, `ExecutableSize` | 플레이어 폴더, `<이름>.exe` |

| `Runtime` | `il2cpp` / `monobleedingedge` / `mono` / `null` |
| `RuntimeKind` | `monobleedingedge-runtime` / `mono-runtime` / `unknown` (점검용) |

## `ScanResult.cs`

### `enum Marker`

보기 콤보박스와 TXT 목록의 종류입니다. `[Flags]`가 아닙니다. 앱의 보기에는 6개만 나오고, 나머지는 `ExportLists`의 목록 정의와 저장 전 검증에 씁니다.

| `Marker` | `SteamScanner.Filter` 조건 | TXT 파일명 | 앱 보기 |
|---|---|---|---|
| `Any` | `!IsBackendUnresolved` | `list_unity_games.txt` | 전체 Unity 게임 |
| `UnityMono` | `ClassifiedBackend == Mono` | `list_unity_mono_games.txt` | Unity Mono |
| `MonoLegacy` | `HasLegacyMono` | `list_legacy_mono_games.txt` | Mono (구형 레거시) |
| `MonoBleedingEdge` | `HasModernMono` | `list_monobleedingedge_games.txt` | MonoBleedingEdge |
| `UnityIl2Cpp` | `ClassifiedBackend == Il2Cpp` | `list_unity_il2cpp_games.txt` | Unity IL2CPP |
| `NestedUnity` | `HasNestedUnity` | `list_nested_unity_games.txt` | 중첩 (Unity 게임) |
| `Managed` | `HasManaged` | `list_managed_games.txt` | — |
| `Nested` | `HasNestedMatch` | `list_samename_game_folders.txt` | — |
| `NestedNonUnity` | `HasNestedNonUnity` | `list_samename_no_unity_detected_games.txt` | — |
| `ShadowedName` | `HasNestedMatch && Backend != Unknown` | `list_shadowed_name_games.txt` | — |
| `RuntimeUnresolved` | `IsRuntimeUnresolved` | `list_runtime_unresolved.txt` | — |
| `BackendUnresolved` | `IsBackendUnresolved` | `list_backend_unresolved.txt` | — |
| `PlayerUnresolved` | `IsBackendUnresolved && (HasAny \|\| AppType == Unknown)` | `list_player_unresolved.txt` | — |
| `NonUnity` | `IsBackendUnresolved && !HasAny && AppType != Unknown` | `list_non_unity_games.txt` | — |
| `Scanned` | 전부 | `list_scanned_games.txt` | — |

보기 항목은 `MainWindow.axaml`의 `ComboBoxItem`에 `Tag="{x:Static local:Marker.…}"`로 붙어 있습니다. 선언 순서와 XAML 항목 순서는 무관하고, 이름을 잘못 쓰면 `AVLN2000` 빌드 에러가 납니다.

| 멤버 | 설명 |
|---|---|

# 스캔

## `SteamScanner.cs` — 조립

### `Scan(roots, progress, catalog)`

```csharp
public static ScanResult Scan(
    IEnumerable<string>? roots = null,
    Action<string>? progress = null,
    SteamCatalog? catalog = null)
```

주 진입점입니다. **동기 함수**라서 화면은 `Task.Run`으로 부릅니다.

| 매개변수 | 설명 |
|---|---|
| `roots` | 스캔할 루트. `null`이면 `FindCommonFolders()`. 없는 경로는 건너뜁니다. `common` 폴더뿐 아니라 게임 폴더 하나(`SteamLibraries.IsGameDirectory`)도 됩니다 |
| `progress` | 진행 문구. **여러 스레드에서 동시에** 불립니다 |
| `catalog` | 쓸 카탈로그. `null`이면 루트들의 라이브러리와 Steam 설치 폴더에서 만듭니다. 테스트는 `SteamCatalog.Empty`나 직접 만든 것을 넘깁니다 |

루트마다 게임 폴더를 `Parallel.ForEach`로 처리합니다. 폴더마다 카탈로그 조회 → `UnityInspector.Inspect` → 같은 이름 하위 폴더 확인 → `lock` 안에서 추가. 끝나면 `NameKey` 순(대소문자 무시)으로 정렬합니다.

- **반환:** 항상 `ScanResult`. 루트가 없으면 `progress`로 알리고 빈 결과
- **예외:** 루트 하나를 읽지 못하면 `Warnings`에 남기고 다음 루트로
- **취소:** 지원하지 않음

### `Filter(result, marker, gamesOnly)`

```csharp
public static IEnumerable<SteamGame> Filter(ScanResult result, Marker marker, bool gamesOnly = false)
```

조건은 위 `Marker` 표입니다. `gamesOnly`가 `true`이고 카탈로그가 있으면 `CountedGames` 안에서만 거릅니다. 카탈로그가 없으면 `gamesOnly`를 무시합니다. 지연 실행(`IEnumerable`)입니다.

### 그 밖

| 멤버 | 설명 |
|---|---|
| `FindCommonFolders()` | `SteamLibraries.FindCommonFolders()`와 같음 |
| `DetectUnityBackend(installDir)` | 폴더 하나의 `Backend`(합집합). `Scan`과 결과가 같음을 `BackendDetectionTests`가 고정 |
| `LibraryRootOf(commonDir)` (internal) | `SteamLibraries.LibraryRootOf`와 같음 |

## `SteamLibraries.cs` — 스캔할 폴더 찾기

### `SplitRootList(text)`

스캔 폴더 입력란의 글을 경로 목록으로 나눕니다. 구분자는 **세미콜론과 줄 바꿈뿐**이고, 쉼표로는 나누지 않습니다(`D:\Games, Old\steamapps\common` 같은 경로가 있기 때문). 앞뒤 공백과 따옴표를 떼고 대소문자만 다른 중복을 뺍니다. 존재 여부는 확인하지 않습니다. `OnScanClick`과 `OnAddFolderClick`이 같이 씁니다.

### `FindSteamPath()`

레지스트리 세 곳을 차례로 보고, 가리키는 폴더가 실제로 있는 첫 경로를 돌려줍니다. 못 찾으면 `null`. 예외를 던지지 않습니다.

| 순서 | 하이브 | 키 | 값 |
|---|---|---|---|
| 1 | `HKEY_CURRENT_USER` | `Software\Valve\Steam` | `SteamPath` |
| 2 | `HKEY_LOCAL_MACHINE` | `SOFTWARE\WOW6432Node\Valve\Steam` | `InstallPath` |
| 3 | `HKEY_LOCAL_MACHINE` | `SOFTWARE\Valve\Steam` | `InstallPath` |

### `FindCommonFolders()`

자동 감지입니다. 예외를 던지지 않습니다.

1. `FindSteamPath()`의 폴더
2. 준비된 드라이브마다 `Program Files (x86)\Steam`, `Program Files\Steam`, `Steam`, `SteamLibrary`, `Games\Steam` 중 있는 것
3. 위 라이브러리마다 `steamapps\libraryfolders.vdf`·`config\libraryfolders.vdf`를 읽어 `"path"` 값을 모읍니다(정규식 `"path"\s*"([^"]+)"`, `\\`만 되돌림). 새로 찾은 라이브러리의 vdf도 이어서 읽습니다
4. 각 라이브러리의 `steamapps\common` 중 실제로 있는 것
5. `FindPreservedGameFolders()`가 찾은 게임 폴더

중복은 대소문자 무시로 뺍니다.

### `FindPreservedGameFolders()`

Steam 밖에 따로 둔 Unity 게임(예: 드라이브 최상위에 복사해 둔 게임)을 찾습니다. 준비된 드라이브마다 **최상위 폴더만** 보고, `IsGameDirectory`가 참인 것을 돌려줍니다. `$`로 시작하는 폴더와 `System Volume Information`, `Windows`, `ProgramData`, `source`, `steam`, `SteamLibrary`는 보지 않습니다.

### `IsGameDirectory(dir)`

폴더 자체가 게임 하나인가. 이름이 `common`이 아니고, 바로 아래에 `.exe`가 있으며, `*_Data` 폴더·`GameAssembly.dll`·`UnityPlayer.dll`·`MonoBleedingEdge\` 중 하나가 바로 아래에 있으면 참입니다. `Scan`은 이런 루트를 하위 폴더 목록이 아니라 게임 하나로 스캔합니다.

### `LibraryRootOf(commonDir)` (internal)

`…\SteamLibrary\steamapps\common` → `…\SteamLibrary`. 부모가 `steamapps`가 아니면 `null`(보존본 게임 폴더 등).

## `UnityInspector.cs` — 폴더 훑기와 플레이어 판정

규칙은 [04-판별 로직](04-판별-로직.md)에 있습니다. 여기서는 구현 특성만 적습니다.

```csharp
public sealed record UnityInspection(UnityBackend Backend, bool HasManaged, bool HasMonoBleedingEdge,
    string? Error, List<BackendEvidence> Evidence, int? DataDirectoryCount);

public static UnityInspection Inspect(string installDir)
```

| 멤버 | 설명 |
|---|---|
| `Inspect` | 공개 진입점. 예외를 던지지 않고 `Error`에 담습니다 |
| `Walk` (private) | 스택으로 한 번만 훑습니다. 보조 마커와 데이터 후보의 가지치기 규칙이 달라서 폴더마다 `DataEligible`을 들고 다닙니다 |
| `AddPlayerEvidence` (private) | `*_Data` 하나 → `BackendEvidence` 하나 |
| `AddRuntimeOnlyEvidence` (private) | `*_Data` 없는 `MonoBleedingEdge\` → 규칙 1-A 증거 |
| `MaxScanDepth` | 8 |
| `IgnoredKeywords` | `MelonLoader`, `BepInEx`, `Voice Editor`, `Modded`, `BackUpThisFolder`, `__MACOSX` (+ `.app`으로 끝나는 이름) |
| `MonoAssemblies` | `Assembly-CSharp.dll`, `Assembly-CSharp-firstpass.dll`, `UnityEngine.dll`, `UnityEngine.CoreModule.dll` |

`IgnoredKeywords`에 `MelonLoader`가 있어서, MelonLoader를 설치하거나 교체해도(`*.replaced-*` 임시 폴더 포함) 판별 결과는 바뀌지 않습니다.

## `SteamCatalog.cs` — 앱 신원과 종류

Steam이 디스크에 남겨 둔 파일에서 앱의 신원과 종류를 읽습니다. 배경은 [09-앱 종류 판별](09-앱-종류-판별.md).

### `enum SteamAppType`

`Unknown` / `Game` / `Demo` / `Application` / `Tool` / `Music` / `Video` / `Config` / `Other`. `appinfo.vdf`의 `common.type` 문자열을 `MapType()`이 옮깁니다(모르는 문자열은 `Other`).

### `sealed class SteamAppEntry`

| 멤버 | 설명 |
|---|---|
| `AppId` | Steam AppID |
| `Name` | 스토어 표기 이름 (없으면 `installdir`) |
| `InstallDir` | `common` 아래 폴더 이름 |
| `Type` | 앱 종류 |

### `sealed class SteamCatalog`

| 멤버 | 설명 |
|---|---|

| `HasApps` | `appmanifest`를 하나라도 읽었는가 |

# 내보내기와 검증

## `GameNames.cs`

`Normalize(name)`: NFC 정규화 → 곡선 아포스트로피(`‘` `’`)를 `'`로 → 연속 공백(유니코드 공백 포함)을 공백 하나로 → 앞뒤 공백 제거. 결과가 `SteamGame.NameKey`입니다.

## `GameExport.cs`

| 멤버 | 설명 |
|---|---|
| `ToText(games, header)` | TXT 본문. 형식은 [10-이름과 내보내기](10-이름과-내보내기.md)「TXT 형식」 |
| `ToJson(games)` | 게임별 분류·증거를 담은 점검용 JSON(`schemaVersion` 4). 앱은 쓰지 않고 테스트와 저장소 밖 점검 도구가 씁니다 |

## `ExportLists.cs`

| 멤버 | 설명 |
|---|---|
| `ExportList(Marker, FileName, Header)` | 목록 정의 하나 |
| `All` | 15개 정의. 파일명은 위 `Marker` 표 |
| `For(marker)` | 그 보기의 정의 |
| `Generate(result, marker, gamesOnly)` | 검증 후 TXT 본문 하나 (「TXT로 저장…」) |
| `WriteAll(result, markers, gamesOnly, folder)` | 검증 후 여러 목록을 한 번에 씀 (「6개 모두 저장…」). 모든 본문을 만든 뒤에 쓰므로 검증 실패 시 파일을 남기지 않습니다. 인코딩은 BOM 없는 UTF-8 |
| `Validate` (private) | 아래 분할이 실제 필터 결과로 성립하는지 확인. 어긋나면 `InvalidOperationException` |

`Validate`가 확인하는 것(모두 같은 `gamesOnly` 범위):

- 범위 안 모든 게임에 `GameClassification.Validate`
- 범위 = Mono ∪ IL2CPP ∪ 백엔드 미확정 (서로소)
- Mono = 구형 레거시 ∪ MonoBleedingEdge ∪ 런타임 미확정 (서로소)
- 범위 = Unity(`Any`) ∪ `NonUnity` ∪ `PlayerUnresolved` (서로소)
- `NestedUnity` ⊆ Unity ∪ `PlayerUnresolved`

## `ScanInventory.cs` — 이전 스캔 대비 누락 검사

분류하지 못한 게임이 목록에서 조용히 사라지지 않게 하는 검사입니다. 화면의 `OnScanClick`이 스캔 직후 백그라운드에서 부르고, 걸린 폴더는 상태 줄 맨 앞에 ⚠ 경고로 보여 줍니다. **스캔을 막지 않습니다.**

| 멤버 | 설명 |
|---|---|
| `InventoryCheck(MissingFolders, LostUnity)` | 검사 결과. `IsClean`, 두 결과를 합치는 `Merge`, 빈 결과 `None` |
| `Baseline(Scanned, Unity)` | 기준선 내용: 모든 `InstallDir`, `Filter(Any)`의 `InstallDir` |
| `BaselineOf(result)` | 스캔 결과 → `Baseline` |
| `CheckPersistent(result, baselineDirectory?)` | 같은 루트 구성의 기준선 파일과 비교하고 기준선을 갱신. 걸린 폴더는 새 기준선에도 남겨 **해결될 때까지 매번 다시 걸리게** 합니다. 파일이 없거나 JSON이 깨졌으면 비교 없이 새로 만듭니다 |
| `Check(previous, current, directoryExists?)` | 두 `Baseline` 비교 (같은 세션의 직전 결과와 비교할 때도 씀) |
| `MissingFolders(...)` | 이전에 있던 폴더 중 **디스크에는 아직 있는데** 이번 결과에서 빠진 것 |
| `LostUnity(...)` | 이전에 Unity였던 폴더 중 디스크에는 아직 있는데 이번에 Unity가 아닌 것 |
| `Compare(...)` / `ValidateUnityRetention(...)` | 위 두 검사의 예외 버전. 걸리면 `InvalidOperationException`. 앱은 쓰지 않고 테스트와 외부 점검용으로 남겨 둠 |

디스크에서 실제로 없어진 폴더는 문제로 보지 않습니다(게임을 지운 것). 기준선 파일은 `%LOCALAPPDATA%\SteamGameTool\scan-baselines\<루트 해시>.json`(`BaselineDirectory`)입니다. 해시는 스캔한 루트 목록(정렬·대문자)의 SHA-256이라서 루트 구성이 다르면 다른 파일입니다. 기존 기준선을 계속 쓰도록 이 계산은 바꾸지 않습니다(`ScanInventoryTests`가 고정).

> 예전(`ValidatePersistent`)에는 검사에 걸리면 예외를 던지고 기준선을 갱신하지 않아서, 폴더 하나가 걸리면 그 폴더를 치울 때까지 모든 스캔이 실패했습니다([07-개선 로드맵](07-개선-로드맵.md) 10번).

## `FakeLibrary` 사용법

```csharp
using var lib = new FakeLibrary();

// '/' 로 끝나면 폴더, 아니면 빈 파일로 만든다.
var game = lib.ScanSingle("MyGame",
    "game_Data/Managed/Assembly-CSharp.dll",
    "MonoBleedingEdge/");

Assert.True(game.HasUnityMono);
```

| 멤버 | 설명 |
|---|---|
| `CommonDir` | `Scan`에 넘길 가짜 `common` 경로 |
| `AddGame(name, params entries)` | 게임 폴더와 그 안의 항목들을 만들고 폴더 경로 반환 |
| `Scan()` | 이 라이브러리만 스캔 |
| `ScanSingle(name, params entries)` | 게임 하나를 만들고 바로 스캔해 그 `SteamGame` 반환 |
